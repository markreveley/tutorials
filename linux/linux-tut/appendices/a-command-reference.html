Appendix A

The working set of commands

The course's roughly seventy commands on one page, grouped by the five audit questions, each with its typical forms, the page that teaches it, and — because task images are minimal — whether a stock ubuntu:24.04 container has it and which package provides it if not.

How to read the tables

The Package column was produced, not remembered: every command was looked up in a fresh ubuntu:24.04 container with command -v, and its owning package found with dpkg -S on the resolved path — before installing anything for commands the image already has, and after apt-get install --no-install-recommends for the rest (raw output in research/verify/a-command-reference.txt). A package name in bold means not in the stock image: an agent that calls it gets 127 (page 27). "builtin" means the shell itself implements it, so it exists wherever bash does (page 2).

In eval work — design

The bold rows are a task-design decision. Calling a tool that isn't installed was the most common failed-command category in Terminal-Bench's analysis, at 24.1% of sampled failures.[Terminal-Bench] If your task instructions say "use jq" or your grader calls curl, the image must contain it; if the task is meant to test whether the agent can cope without it, say so in the task's documentation, so a reviewer codes those failures as the model's and not the environment's.

To answer "which package gives me X?" yourself, inside any Debian or Ubuntu box: 

# dpkg -S "$(readlink -f "$(command -v ps)")"
procps: /usr/bin/ps
# dpkg -S /usr/bin/ip
dpkg-query: no path found matching pattern /usr/bin/ip
# dpkg -S /bin/ip
iproute2: /bin/ip

The middle line is a trap worth knowing. Ubuntu merged /bin into /usr/bin, but some packages still register their files under the old /bin path, so dpkg -S on the /usr path finds nothing. Try both before concluding a file is unowned. dpkg -S only searches installed packages; for a tool not yet installed, apt-cache search or the Ubuntu package website is the route (page 15).

Pitfall — man exists but doesn't work

ubuntu:24.04 has a /usr/bin/man, but it is a stub installed by a dpkg diversion; running it prints This system has been minimized by removing packages and content that are not required on a system that users do not log into. Read man pages on man7.org instead (Appendix F). Similarly, dnsutils still installs, but it is now a transitional package that depends on bind9-dnsutils, which is where dig and nslookup live.

Caveat — Alpine and macOS differ

The package column is Ubuntu 24.04's. On Alpine most of the base commands are BusyBox applets with fewer options, and package names differ — check with apk in the image rather than assuming (page 15). On your Mac, many of these commands exist with BSD behaviour or not at all (Appendix E); run them in the lab container.
