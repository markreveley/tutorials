Appendix B · Evidence at the terminal

Command reference

Commands are useful when you can state what their output establishes. Examples use loopback, public example.com, or clearly marked placeholders.

Before collecting evidence

Record where the command runs: laptop, container, Pod, or CI worker. Check tool availability and version. Use credential-free endpoints for routine probes and redact any sensitive headers or URLs before sharing output. Placeholder commands below need the real authorized names; do not paste them unchanged.

Measure a simple HTTPS transfer

curl -sS -o /dev/null --connect-timeout 5 --max-time 20 \
  -w 'dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first_byte=%{time_starttransfer} total=%{time_total} status=%{http_code}\n' \
  https://example.com/

Times are seconds measured cumulatively from transfer start. Differences can approximate phases for a simple fresh connection, but redirects, proxies, reuse, and protocol differences need care. First byte is not first token. A status of 000 indicates that curl did not obtain an HTTP response status; inspect its error and exit code.

Isolate DNS without changing TLS identity

curl --resolve api.example.test:443:192.0.2.10 \
  --connect-timeout 5 --max-time 15 https://api.example.test/health

This is schematic: example.test and 192.0.2.10 are documentation placeholders. Replace them with an approved hostname, port, and verified address for your service. The URL hostname remains the TLS/HTTP identity. The result tests the chosen address, not ordinary DNS behavior; remove the override after the experiment.
