Cloud networks without the mystery

A cloud diagram becomes easier to read when you separate addressing, routing, traffic permission, and application identity.

Read the pieces independently

A cloud virtual network groups configurable addressing and network connectivity. AWS calls this a VPC. A subnet is a range within that network; in AWS it belongs to one availability zone. Route tables decide where traffic goes. Security groups and other controls decide which traffic is allowed. Application credentials decide what a reached service permits. These mechanisms solve different problems.[vpc]

QuestionTypical component
Which addresses can we allocate?VPC and subnet CIDR ranges.
Where does a packet for this destination go?Route table and next hop.
May this connection pass?Security group, firewall, network ACL, or policy.
How does private IPv4 traffic reach a public service?An explicit outbound design, often NAT plus an Internet path.
Which service can this identity use?IAM/application authorization, beyond basic reachability.

A worker in a private subnet

A private subnet does not directly route to an Internet gateway. It can still have outbound Internet access through a configured path such as a public NAT gateway in a public subnet. For ordinary IPv4 Internet access, appropriate source addressing or translation is also needed. A public subnet alone does not make every instance reachable.

A managed NAT gateway tracks outgoing connections and translates return traffic. It does not grant remote systems a general ability to initiate inbound connections to private workers. At scale, connection capacity, idle lifetimes, and ports can become relevant. Before diagnosing rare connection errors as “the model is flaky,” inspect the outbound component’s metrics.[nat]

Network permission is not application permission

AWS security groups are stateful allow controls: return traffic for an allowed connection is treated differently from an unrelated new connection. Network ACLs are separate subnet-level controls with different semantics. Do not carry a rule recipe from one product to another without checking its model. Opening an inbound port on a worker is normally unrelated to its need to initiate an outbound HTTPS connection.[sg]

Private service endpoints, VPNs, and peering can provide additional paths. Ask which exact service and region a private endpoint covers, how its DNS behaves, and which identity policy applies. “It is private” does not prove all dependencies use private paths or that every identity is authorized.

Questions that make a review productive

State the worker’s region, subnet, DNS view, outbound route, destination, port, and identity. Trace dataset download, model calls, grading, and result upload separately. A model call can succeed while result storage fails because those are different dependencies. Record whether a path crosses regions or zones when discussing latency and transfer costs; verify current pricing when estimating actual spend.

Check your understanding

A cloud worker can reach an internal database but cannot call a public model API. Does the database connection prove the network is fine?

Reveal the reasoning

It proves a particular internal path worked. Public model access can use different DNS, routes, gateways, firewall rules, and identities. Investigate the model path from the worker’s subnet, including its outbound route and any NAT or proxy.
