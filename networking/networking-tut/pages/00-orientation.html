Module 0 · The professional baseline

What networking competence looks like

You are learning to reason about the infrastructure around an evaluation: where a request goes, what can fail, what to measure, and how to explain a design. No networking background is assumed.

The job this course prepares you for

An evaluation can involve a laptop, a fleet of workers, a model provider, a grading service, a database, and a sandbox that lets an agent use tools. Each connection introduces time, cost, permissions, and ways to fail. Your score depends on that infrastructure behaving as intended. A dropped request is an observation about the run; it is not automatically evidence that a model lacks a capability.

The useful professional standard is concrete: draw the request path, explain the role of each component, distinguish evidence from a hypothesis, and propose a bounded experiment. You do not need to configure an Internet backbone to do these things. You do need to know what a route, a port, a timeout, and a proxy mean.

The recurring example

We are evaluating 10,000 prompts against a model API. Workers read a dataset, send requests, preserve the responses and timing, and hand completed attempts to a grader. Some attempts will fail. Our job is to make those failures explainable.

How to use the course

Read the lessons in order the first time. Each introduces a small set of terms, uses them in an eval scenario, and ends with a question whose answer you can reveal. Say your answer out loud before opening it. Follow the glossary links whenever a noun is unfamiliar; needing a definition is part of learning.

Work the local service lab after the diagnostic lessons. It requires Python 3 and curl, but no cloud account, model API key, Docker installation, or paid service. The course pages themselves open directly from disk. External reading links need an Internet connection; all of the explanations and local experiments are included here.

The book you supplied, Computer Networks: A Systems Approach, is the foundation for the underlying concepts. This course follows a request through the system rather than following every book chapter. Official protocol and infrastructure documentation supplies the implementation details. The annotated bibliography separates those sources from the course’s own design exercises.

A realistic finish line

This is a networking component of professional preparation, not a promise of employment. The final review asks you to explain and defend an eval design, reproduce a failure, and keep infrastructure outcomes separate from model outcomes. Those are observable skills you can demonstrate.

Check your understanding

A benchmark score falls after moving workers from your laptop into a cloud network. What would you establish before blaming the model?

Reveal the reasoning

Check whether the same examples produced complete responses under the same request settings. Compare infrastructure failures, deadlines, retries, region, concurrency, and scoring policy. A deployment change can alter which examples finish and therefore which examples reach the grader.
