DNS: names, answers, and context

DNS helps a program turn a name into information it can use to connect. A correct answer is one step toward a working request.

What resolution actually means

A client asks a resolver for records associated with a name. A recursive resolver can consult other DNS servers and cache results. Authoritative servers publish records for their zones. The client usually does not visit every part of that hierarchy itself. A local cache, an operating-system configuration, a container resolver, or a corporate VPN can all affect the answer.[dns]

Record or responseWhat it tells you
AAn IPv4 address associated with a name.
AAAAAn IPv6 address associated with a name.
CNAMEAn alias to another DNS name.
TTLA lifetime used for caching a record; it is not a connection timeout.
NXDOMAINThe queried name does not exist according to this DNS response.
SERVFAILThe DNS server could not successfully answer; the name is not thereby proven nonexistent.

Caching explains why two workers can temporarily use different answers after a change. Also distinguish DNS caching from connection reuse: an existing connection can remain attached to an old backend even after a DNS record changes. Lowering a TTL does not forcibly reconnect clients or evict previously cached records immediately.

Resolve from the environment that fails

Suppose your laptop resolves model.internal, but a CI worker does not. The laptop may be using a VPN resolver with a private zone. A public resolver does not necessarily know that zone. The useful question is which resolver the failing process uses and whether it can reach it. Asking an unrelated public DNS server can test a different system.

dig example.com A
dig example.com AAAA
python3 -c 'import socket; print(socket.getaddrinfo("example.com", 443))'

These commands make live DNS queries, so outputs vary. dig may need installation on some systems. Python’s lookup follows the operating system’s name-resolution interfaces; it can differ from a direct DNS query because of hosts files and local resolver behavior. Inspect the DNS status and answer section, not just whether the command printed text.

Separate name resolution from connectivity

If a hostname resolves to an address but HTTPS fails, DNS has supplied a candidate destination; routing, connections, TLS, or HTTP may still fail. Conversely, substituting an IP directly into an HTTPS URL changes the requested identity. A certificate for a hostname need not cover that address.

For a controlled diagnostic on a known endpoint, curl’s --resolve hostname:port:address supplies an address while preserving the URL hostname for HTTP and TLS. Obtain the address from an approved source and record the override. It is a way to isolate name resolution, not a permanent hard-coded fix. See the command appendix for an example.[curl]

Common mistake

“DNS propagated” is too vague for an incident report. Say which name, record type, resolver, environment, time, and answer you observed. A private DNS view and a public DNS view can intentionally disagree.

Check your understanding

The service moved to a new address ten minutes ago, but one long-running worker keeps hitting the old backend. Must its DNS cache be broken?

Reveal the reasoning

No. It may be reusing an already-open connection and therefore not performing a new lookup. Check connection lifetime as well as cached DNS records, TTLs, and any intermediate proxy’s resolution behavior.
