Proxies, gateways, and load balancers

The machine answering your connection may be an intermediary. Learn what it owns before attributing its behavior to the model.

Several roles can share one component

A forward proxy acts for clients making outbound requests. A reverse proxy stands in front of servers. A load balancer distributes traffic over backends. An API gateway often combines reverse proxying with authentication, quotas, routing, and other HTTP policy. One product can perform several of these jobs.[http]

A Layer 4 balancer can make decisions using connection information. A Layer 7 proxy can inspect HTTP and route by host, path, or headers. If it decrypts client HTTPS to inspect messages, identify where TLS terminates and how the backend connection is protected. Do not infer the trust boundary from a product name alone.

Load balancing does not mean equal work

One long-lived connection can carry many requests. Whether those requests reach several backends depends on the protocol and balancing layer. Counting connections may be a poor estimate of model load when request sizes differ substantially. A single long output can occupy capacity far longer than a short answer.

Readiness checks help decide which backends should receive new traffic. A port being open is weaker evidence than a successful application-level readiness check. Even an HTTP health endpoint can be green while model weights are unavailable or the real inference path is overloaded. Ask what the health check actually tests and what it costs.

Find the intermediary’s limits

PolicyPossible eval symptom
Request body limitLarge prompts fail while small prompts succeed.
Upstream timeoutRequests fail after a consistent elapsed time.
Response bufferingStreaming appears in bursts or all at once.
Idle timeoutLong gaps in a stream trigger disconnection.
Header or auth policyA direct backend call works but the supported gateway route fails.
Backend selectionOne subset of requests fails on a particular replica.

A 502 or 504 tells you about an intermediary’s problem with an upstream exchange. It does not identify every component in the chain. Correlate gateway logs with a request ID, selected backend, upstream duration, and termination reason. If the platform supplies these fields, they can be more useful than repeatedly trying the same request from a laptop.

Invisible proxy configuration

Clients may honor HTTP_PROXY, HTTPS_PROXY, and NO_PROXY, with behavior that varies by client. A proxy can change resolution location, certificates, reachable destinations, and timing. Inspect relevant configuration without dumping credential-bearing environment values into a shared log. A direct curl test and an SDK request may take different routes.

Check your understanding

Small prompts succeed; large prompts receive 413 almost immediately. Should you increase inference timeout?

Reveal the reasoning

First inspect request-size limits at the responding gateway and the API contract. An immediate rejection of the request body is different from slow inference. Record payload size and response provenance, and establish the supported limit before changing timeouts.
