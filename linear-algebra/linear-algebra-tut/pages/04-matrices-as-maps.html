Module 1 · Linear maps

Matrices as linear maps

A weight matrix is a function from one vector space to another. Its shape is its type signature, and linearity is the promise that it treats sums and scalings honestly.

A matrix is a function

A linear map is a function f from vectors to vectors that respects the two operations of lesson 01: f(u + v) = f(u) + f(v) and f(c·u) = c·f(u). Rotations, reflections, stretches, and projections are linear; translation (adding a fixed vector) is not, and neither is anything that squares a coordinate. The useful fact is that a linear map from d-dimensional to h-dimensional space is completely determined by what it does to d basis vectors, and writing those h-vectors side by side gives a (d, h) grid of numbers: a matrix. Applying the map is multiplying by the matrix. The 3Blue1Brown chapter on linear transformations animates the plane being sheared and rotated by a 2×2 matrix; the lesson here does the same with a 768×64 one.

x of shape (d,), W of shape (d, h)
y = x W has shape (h,), with yⱼ = Σᵢ xᵢ Wᵢⱼ = x · (column j of W)

Read the formula as h dot products: output coordinate j is the dot product of the input with column j of W. Each column of W is a direction in the input space, and the map measures the input along each of those directions. That is why lesson 03 came first. A linear map from 768 to 64 dimensions is 64 projections, bundled.

The convention here, x W with x as a row, matches numpy and PyTorch, where a batch of row vectors X of shape (n, d) multiplies W on the right to give (n, h). Textbooks often write W x with x as a column and W of shape (h, d); the two are transposes of each other and say the same thing. When reading code or a paper, find out which convention is in use before interpreting a shape.

A real weight matrix

The fixture includes W_Q for attention head 0 of layer 7, which reads the residual stream the fixture caches. Its shape is (768, 64): it takes an activation and produces a 64-dimensional query vector. The lab applies it to token 12 and checks linearity on real numbers.

python3 labs/linalg_lab.py shapes
x = token 12 '42': shape (768,)
W_Q shape (768, 64): maps a 768-vector to a 64-vector
q = x @ W_Q: shape (64,); first five [  3.636  -9.206   6.943 -14.039  19.925]
q is a linear map of x: check (2x) @ W_Q == 2 (x @ W_Q): True
and (x + x2) @ W_Q == x @ W_Q + x2 @ W_Q: True
column 0 of W_Q, first five entries [ 0.095 -0.082 -0.038 -0.112  0.025]: q[0] = x . column 0 = 3.636
W_O shape (64, 768): maps a 64-vector back to 768. (x @ W_V) @ W_O has shape (768,)
x @ W_O fails: matmul: Input operand 1 has a mismatch in its core dimension 0, with gufunc signature (n?,k),(k,m?)->(n?,m?) (size 64 is different from 768)
W_O @ x runs, shape (64,): shapes happen to match, but it dots x with the rows of W_O, which is not the map the head applies

The first output coordinate, 3.636, is the dot product of the 768-vector x with the first column of W_Q, whose first five entries are shown. The two True lines are linearity, checked numerically: doubling the input doubles the output, and the map of a sum is the sum of the maps. The last two lines are the type system doing its job, and then failing to. W_O has shape (64, 768) and expects a 64-vector on its left; given x of length 768 there, numpy refuses, and the error names the mismatched dimension. A shape error at this stage is a gift. The dangerous errors are the ones where shapes happen to match and the meaning does not: W_O @ x runs, because (64, 768) times (768,) is a legal product, but it dots x with the rows of W_O, treating the head’s output directions as things to measure x against, which is not what the head computes. Nothing in the shapes tells you that; only knowing which convention the matrix was stored in does.

Reading shapes as types

Write the type of each map in the head as W_Q : ℝ⁷⁶⁸ → ℝ⁶⁴, W_K : ℝ⁷⁶⁸ → ℝ⁶⁴, W_V : ℝ⁷⁶⁸ → ℝ⁶⁴, W_O : ℝ⁶⁴ → ℝ⁷⁶⁸. Then the composition that reads a value from one token and writes it back to the residual stream, x ↦ (x W_V) W_O, type-checks: ℝ⁷⁶⁸ → ℝ⁶⁴ → ℝ⁷⁶⁸. The composition x ↦ (x W_Q) W_O does not, and there is no need to know anything about attention to see it. Lesson 05 makes composition itself a matrix; the transformers course explains what the head does with these maps.

Three maps to recognise

The identity matrix I, ones on the diagonal and zeros elsewhere, is the map that returns its input. A diagonal matrix scales each coordinate separately. A matrix of the form d̂ d̂ᵀ, the outer product of a unit vector with itself, has shape (d, d) and sends x to (x · d̂) d̂: it is the projection of lesson 03 written as a matrix, and I − d̂ d̂ᵀ is the map that keeps the residual. Lesson 08 uses the second of these to remove a direction from every activation with a single matrix product.

In interpretability work

Every weight matrix in a transformer is a linear map between named spaces: residual stream to head space, head space to residual stream, residual stream to vocabulary. Name the spaces, write the types, and you can predict the shape of any quantity in a paper before reading its definition. A probe direction is a (768,) vector; a probe is a map ℝ⁷⁶⁸ → ℝ; an unembedding is ℝ⁷⁶⁸ → ℝ⁵⁰²⁵⁷.

Pitfall

Assuming the stored orientation of a matrix matches your convention. The fixture’s W_O is (64, 768) because the transformers library stores it to be applied as v @ W_O; another library may store its transpose. Shapes tell you which; a product that “works” after a stray transpose is the hardest bug to find.

Check your understanding

A map sends (1, 0) to (2, 1) and (0, 1) to (−1, 3). Where does it send (3, 2), and what is the matrix in the row-vector convention?

Reveal the reasoning

By linearity, (3, 2) = 3·(1, 0) + 2·(0, 1) goes to 3·(2, 1) + 2·(−1, 3) = (6 − 2, 3 + 6) = (4, 9). In the row-vector convention the images of the basis vectors are the rows: W = [[2, 1], [−1, 3]], and (3, 2) W = (3·2 + 2·(−1), 3·1 + 2·3) = (4, 9). In the column convention the same map is the transpose. The map is determined by two images because every input is a combination of the two basis vectors.

Practice

Apply W_Q to the outlier token 0 and compare the size of its query vector with token 12’s.

python3 labs/linalg_lab.py shapes --token 0
What to look for

The query vector of token 0 is roughly thirty-six times larger coordinate for coordinate, because the map is linear and the input is about thirty-six times longer. In the real model a layer norm precedes W_Q and would rescale the input; the fixture omits it on purpose. Linearity means scale passes straight through, which is exactly why normalisation layers exist.
