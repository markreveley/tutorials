Appendix A · Math & Stats

Probability Basics

Everything in eval statistics — error bars, significance tests, pass@k — rests on a handful of probability ideas. This appendix builds them from zero, using one running example: a model that answers each eval question correctly with probability 0.7.

What probability means

Suppose you have an eval — a fixed set of questions you put to a model, each graded pass or fail. Take one question from it. You run the model on that question over and over (with temperature above zero, the model's output varies from run to run). Out of the first 10 attempts it passes 8. Out of 100, 73. Out of 10,000, 7,012. The fraction of passes keeps wobbling, but less and less, settling toward some value — say 0.7.

That settling point is what we'll mean by probability: the long-run fraction of times an outcome occurs if you could repeat the experiment indefinitely under the same conditions. "This model answers this question correctly with probability 0.7" means: repeat it forever, and 70% of attempts pass. There are deeper philosophical readings of probability, but for this course the long-run-frequency reading is all you need.

Two immediate consequences. First, probabilities live between 0 (never happens) and 1 (always happens). Second — and this is the part people forget — a probability tells you almost nothing about any single attempt. With p = 0.7, the next attempt might pass or fail, and nothing about the number 0.7 tells you which. Probability is a statement about the aggregate, not the instance.

Key idea Probability = long-run frequency. It describes what happens over many repetitions, never what happens next. Every statistical tool in this course is a way of reasoning backward from a small number of repetitions to that long-run frequency.

Random variables

A random variable is just a number whose value depends on chance. Despite the intimidating name, that's the whole definition. "The number showing on a die I'm about to roll" is a random variable. "The number of questions a model will pass on tomorrow's eval run" is a random variable. Before the experiment happens, the value is unknown; after, it's an ordinary number.

Here is the single most important reframe in this course: the score of an eval run is a random variable. When you run a 100-question eval and get 73%, that 73% is one realized value of a quantity that could have come out differently — different sampled outputs, different luck. Run it again and you might get 69% or 76% with nothing about the model having changed. Module 5 (Error Bars on Eval Scores) is entirely about taking this seriously.

We'll write random variables with capital letters. For our running example, let X be the result of the model attempting one question: X = 1 if it passes, X = 0 if it fails.

Bernoulli trials and independence

A random variable that can only be 0 or 1 — fail or pass — is called a Bernoulli trial. It's the simplest random variable there is, and it's everywhere in evals: every binary-graded question, every unit test that passes or fails, every judge verdict of "acceptable / not acceptable" is a Bernoulli trial. A Bernoulli trial is fully described by one number, the probability of a 1. We write X ~ Bernoulli(p), and in our running example p = 0.7.

Now take a whole eval: n questions, each one a Bernoulli trial. To say anything about the total score we need one more concept. Two trials are independent if the outcome of one tells you nothing about the outcome of the other — knowing the first question passed doesn't change the 0.7 probability for the second. Coin flips are independent; whether it rains today and whether it rains tomorrow are not (weather persists).

Independence is an assumption, and in evals it's sometimes false in ways that matter. If your eval contains five questions about the same document, a model that misreads that document will likely fail all five together — those failures are correlated, not independent. Statistics built on an independence assumption will then overstate how much you know (this is why clustered standard errors exist). For this appendix we'll assume independence holds; just remember it's something you assert, not something you get for free.

Expectation: the long-run average

The expectation (or expected value) of a random variable, written E[X], is its long-run average: the value you'd get by averaging infinitely many repetitions. For a variable taking finitely many values, you compute it as a weighted average — each possible value times its probability, summed up.

For our Bernoulli trial with p = 0.7:

E[X] = 1 × 0.7 + 0 × 0.3 = 0.7 = p

In words: a pass/fail variable's long-run average is just its pass probability. This tidy fact is why pass rates and pass probabilities are interchangeable: the fraction of 1s you observe over many trials converges to p.

Note that E[X] = 0.7 even though X itself can never equal 0.7 — it's always exactly 0 or exactly 1. "Expected value" does not mean "the value you expect on any given trial"; it means the average over many trials. The name is genuinely misleading and you just have to get used to it.

Linearity of expectation. Expectations add, always: E[X + Y] = E[X] + E[Y]. In plain words, the long-run average of a sum is the sum of the long-run averages. Remarkably, this holds whether or not X and Y are independent — averages don't care about correlation. So if a model attempts 10 questions, each with pass probability 0.7, the expected number of passes is 0.7 + 0.7 + … + 0.7 = 7, no independence required. Linearity is the workhorse behind almost every formula in Appendices B and D.

Variance and standard deviation: spread

The expectation tells you where outcomes center; it says nothing about how far they scatter. Two evals could both average 70% while one swings between 60% and 80% and the other barely moves. The standard measure of scatter is variance: the average squared distance between the variable and its expectation.

Var(X) = E[(X − E[X])2]

In words: take how far each outcome lands from the long-run average, square it (so misses in either direction count positively), and average those squared misses. For a Bernoulli(p) variable this works out to a famous closed form. With p = 0.7, the expectation is 0.7; a pass (value 1) misses it by 0.3, a fail (value 0) misses it by 0.7. Weighting each squared miss by its probability:

Var(X) = 0.7 × (1 − 0.7)2 + 0.3 × (0 − 0.7)2 = 0.7 × 0.09 + 0.3 × 0.49 = 0.063 + 0.147 = 0.21

And in general:

Var(X) = p(1 − p)

In words: a pass/fail variable's variance is the pass probability times the fail probability. Check it on our example: 0.7 × 0.3 = 0.21. ✓

The formula p(1 − p) is worth staring at. It equals 0 when p = 0 or p = 1 — if the model always fails or always passes, there's no scatter at all, every trial is identical. It's largest at p = 0.5, where it equals 0.25. That's the intuition: p = 0.5 is maximum uncertainty — a coin flip, passes and fails equally likely, outcomes as unpredictable as a binary outcome can be. The further p gets from 0.5 in either direction, the more predictable each trial becomes, and the variance shrinks. One practical consequence: eval scores near 50% are the noisiest, run to run, of any score.

Variance has awkward units — it's in squared passes. Taking the square root fixes that. The standard deviation is σ = √Var(X), and it lives on the same scale as the variable itself, which makes it the number you can actually picture: roughly, the typical distance of an outcome from the average. For our single question, σ = √0.21 ≈ 0.458.

The binomial distribution

Now run the whole eval. Let S be the total number of passes across n independent questions, each Bernoulli(p). The probability of each possible total — P(S = 0), P(S = 1), …, P(S = n) — follows the binomial distribution. The formula: there are C(n, k) different ways to choose which k questions pass (C(n, k) counts combinations; see Appendix D), and each particular pattern of k passes and n − k fails has probability pk(1 − p)n−k by independence. So:

P(S = k) = C(n, k) × pk × (1 − p)n−k

In words: the chance of exactly k passes is the number of ways to place them, times the probability of any one placement. Its mean and variance follow directly from the single-trial results: linearity of expectation gives the mean, and independence lets the single-trial variances add up the same way.

E[S] = np      Var(S) = np(1 − p)

In words: the expected number of passes is the per-question pass probability times the number of questions, and the spread around that grows with both n and the per-question uncertainty p(1 − p).

Worked example: a 10-question eval, p = 0.7. Our model takes a 10-question eval; each question independently passes with probability 0.7. Let S be the number it gets right.

Mean: E[S] = 10 × 0.7 = 7. Variance: Var(S) = 10 × 0.7 × 0.3 = 2.1. Standard deviation: σ = √2.1 ≈ 1.45. So a typical run lands around 7 passes, give or take about a question and a half.

Probability of exactly 7 passes: there are C(10, 7) = 120 ways to choose which 7 questions pass. Each such pattern has probability 0.77 × 0.33 = 0.0823543 × 0.027 ≈ 0.0022236. So

P(S = 7) = 120 × 0.0022236 ≈ 0.267

The single most likely outcome — the true score, 70% — happens barely a quarter of the time. The same arithmetic for the neighbors gives P(S = 8) = 45 × 0.78 × 0.32 = 45 × 0.05764801 × 0.09 ≈ 0.233 and P(S = 6) = 210 × 0.76 × 0.34 = 210 × 0.117649 × 0.0081 ≈ 0.200. Roughly a 30% chance the run reports something outside 60–80% entirely.

Why this matters for evals

Look at that diagram again and let it sink in: a model whose true per-question ability is exactly 70% will report 50% on one run in ten, and 90% or better about one run in seven. Nothing changed between runs except luck. With more questions the spread narrows — relative to the maximum score, the standard deviation shrinks like 1/√n — but it never reaches zero, and small evals (a few dozen samples is common in practice) are far noisier than people's intuitions suggest.

Pitfall Treating a single eval run's score as the score. "Model A got 73%, model B got 70%, so A is better" is exactly the mistake this appendix should inoculate you against: on our 10-question eval, two runs of the same model report different scores 81% of the time, and differ by 20 percentage points or more nearly half the time (46%). A single score is one draw from a distribution. Before you compare scores, you need to know how wide that distribution is — that's what error bars are for.
