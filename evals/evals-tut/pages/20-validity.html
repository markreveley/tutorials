Module 6 · Contamination & Validity

What does a score mean? Validity

Modules 1–5 taught you to build evals and to handle their noise. This module confronts the failure no error bar can catch: a score that is precise, reproducible, and about the wrong thing. The concept that organizes the whole module is validity — and it comes from measurement science, not machine learning.

The proxy chain

You never measure what you care about. You care about something abstract — "this model can do real software engineering," "this assistant is safe" — called the construct in measurement theory. What you measure is the end of a chain of stand-ins:

what you care about "can it do real software engineering?" │ (construct) ▼ a task family resolve GitHub issues ▼ a dataset 2,294 issues from 12 Python repos ▼ a grader do the PR's tests pass? ▼ a number "33.2%"

Construct validity is the question of whether the whole chain holds — whether the number at the bottom still says something about the idea at the top. Every link is a place it can break, and Modules 1–5 have already collected verified breaks for each one. The EleutherAI reproducibility paper states the right default posture in one line: "The appropriate conclusions to draw about a model's behavior are informed by, not constituted by, these numerical scores."[Eleuther] The score is evidence about the construct, never the construct itself.

Two cousins of construct validity complete the vocabulary. Internal validity: is the comparison clean within the experiment — or did task ordering, environment state, or an unvalidated judge contaminate it? External validity: does the result transfer beyond the eval's conditions? METR's time-horizon work is unusually honest about the latter: the metric is defined relative to a task distribution and a reference human population, and switching that population from repository maintainers to external contractors shifts measured task times by 5–18×[METR] — the same model, a several-fold different "horizon."

Three cheap probes for a broken chain

Validity sounds philosophical; testing it is mostly mechanical. Three probes, each verified in action earlier in this course:

1. The control check: what would a broken system score? Anthropic's models scored a perfect bias score of 0 on the BBQ benchmark — because they weren't answering the questions at all, and the metric couldn't tell.[Anthropic] If a trivial, broken, or constant system scores well, the chain is broken above the metric. (Page 28 runs this same probe on claims about a neuron.)

2. The ablation: remove an input the construct requires. tau-bench's authors deleted the policy document their benchmark supposedly tests adherence to; the retail score barely moved (−4.4), revealing that successes "mostly stem from using tools in an intuitive and common sense way" — not the construct on the label.[tau-bench]

3. The fresh-instance replication: re-pose the task with new data. If the score drops on new instances matched for difficulty, the old score was partly measuring familiarity, not ability. This is the GSM1k method — the next page — and the SWE-Bench+ arc (12.47% → 0.55%) was its agentic cousin.[SWE-bench+]

Validity decays: saturation and Goodhart

A benchmark's validity isn't fixed at construction — it erodes through use, by two mechanisms. Saturation: as models approach the ceiling, the benchmark stops discriminating — remaining gaps are noise and label errors (recall that Anthropic found mislabeled and unanswerable items in MMLU itself: even "ground truth" has an error rate[Anthropic]). And targeting: once a measure carries stakes, it gets optimized as a measure. The verified small-scale case is leaderboard models fine-tuned to match lm-eval separator tokens[Eleuther]; the industrial-scale case is page 23. Both are Goodhart's-law dynamics: pressure on the proxy detaches it from the construct precisely because it's a proxy.

Pitfall

Equating "rigorous" with "quantitative." A team that replaces judgment with an invalid number has not become more scientific — it has laundered a guess through arithmetic. The BBQ-zero story is the canonical miniature: the number was exact, the pipeline reproducible, the conclusion ("we reduced bias") false. Rigor is the chain holding end to end, not the precision of the last link.

Key idea

Ask of every score: valid for what? A score is valid for a use, not in general — SWE-bench Verified numbers are informative for comparing coding agents and nearly mute on "will this agent handle my legacy codebase." The rest of this module covers the most consequential way the chain breaks — the test set leaking into training — the defenses, and what stakes do to measurements.
