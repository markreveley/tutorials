Anatomy of an eval

Between "the dataset" and "the score" sits a piece of software full of judgment calls — the harness. Two teams running the same benchmark on the same model can get scores tens of points apart because of decisions buried in that software. This page opens the box.

What actually runs

The four-part machine from the previous page — task, data, grader, metric — is the logical anatomy. The harness is the physical one: the program that feeds each sample to the system under test, captures what comes back, applies the grader, and aggregates. Drawn honestly, with the parts that usually go unmentioned in highlighted boxes:

Each numbered box is a decision someone made. None of them sound important. All of them move scores — and the evidence for that comes from teams who run evals at industrial scale.

❶ The prompt template moves scores by tens of points

EleutherAI — maintainers of lm-evaluation-harness, one of the most widely used eval harnesses — documented what happens when the same questions are presented in two common prompt styles ("cloze," where the model completes the answer text, versus MMLU-style, where it picks a letter). For GPT-NeoX-20B on the ARC-Easy benchmark, the cloze format scored 72.4%; the MMLU-style format scored 26.5% — barely above chance, a swing of roughly 46 points from formatting alone.[Eleuther] Worse for comparability: which style works best varies by model, so prompt choice changes model rankings, not just absolute numbers.[Eleuther] The paper notes that sensitivity goes "even down to whitespace usage."

Anthropic, writing from a frontier lab's vantage point, reported the same phenomenon at finer grain: changing answer options from (A) to (1), or (A) to [A], or adding one extra space before the answer "can lead to a ~5% change in accuracy" on MMLU.[Anthropic] Five points is larger than the margin separating headline model releases.

The counterfactual that makes it vivid

The EleutherAI authors point out that if MMLU-style prompting had been the standard during the GPT-3 era, their Pile-trained models would have scored near-random — and they "might have wrongly concluded their dataset was garbage."[Eleuther] Research directions live and die on numbers this fragile.

❷ Decoding and ❸ extraction: the quiet score-makers

The model call itself has knobs — temperature, token limits, retry policy — and they interact with the metric in non-obvious ways. The HumanEval authors found that the optimal temperature depends on which metric you report: low temperature (0.2) maximized pass@1 while high temperature (0.8) maximized pass@100, because when only one of a hundred attempts needs to succeed, diversity beats caution.[HumanEval] Headline numbers from the same paper, same model, can come from different decoding settings — and routinely do.

Then the harness must find "the answer" inside free-form text. The standard tool is a regex or heuristic parser, which EleutherAI calls "a highly imperfect solution": models answer in different formats, so any fixed pattern silently favors models whose format happens to match — conflating format compliance with correctness.[Eleuther] A model that says "The answer is B, because…" scores; one that says "B is correct because…" may not, depending on five characters of regex.

❹ Scoring method and ❺ aggregation

Multiple-choice questions can be scored two fundamentally different ways: generatively (let the model write an answer, extract, compare) or by log-likelihood (ask which option the model assigns the highest probability — no text generated at all). These are different measurements, and empirically they disagree: the EleutherAI paper cites work showing that log-likelihood-scored and generatively-scored versions of the same multiple-choice benchmarks "do not even agree."[Eleuther] Many model APIs don't expose probabilities, which forces the generative route — meaning published comparisons between API models and open models are sometimes comparing two scoring methods, not two models.

Even pure arithmetic hides choices. MMLU has 57 subjects of different sizes: do you average over all questions (micro) or average the 57 per-subject accuracies (macro)? The correct convention is micro, the difference "affects results by several percentage points," and papers usually don't say which they did.[Eleuther] The consequence of all five decision points together: three independent implementations of MMLU (HELM, lm-eval, and the original release) "produce widely different scores and even change the ranking order of models" — same benchmark, same models, different truths.[Eleuther]

A toy harness, decisions annotated

Here is a minimal but honest harness for a yes/no classification eval. Every comment marks a decision that would change the score: 

import re

def run_eval(model, dataset):
    scores = []
    for sample in dataset:
        # ❶ template: wording, capitalization, trailing space all matter
        prompt = f"Q: {sample['question']}\nAnswer yes or no.\nA:"

        # ❷ decoding: temperature 0 here; retries on API error not shown —
        #    does a third timeout count as a failure or get dropped?
        text = model.generate(prompt, temperature=0, max_tokens=5)

        # ❸ extraction: this regex accepts "Yes."/"yes" but rejects
        #    "Definitely yes" — is that a wrong answer or a parsing gap?
        m = re.match(r"\s*(yes|no)\b", text.lower())
        predicted = m.group(1) if m else None

        # ❹ scoring: unparseable output counts as wrong (a choice!)
        scores.append(1 if predicted == sample["answer"] else 0)

    # ❺ aggregation: plain mean — no error bars, no per-slice breakdown
    return sum(scores) / len(scores)

Twenty lines, five judgment calls. Real harnesses make dozens more.

Reading a harness critically

A skill this course will drill repeatedly, especially for agentic benchmarks (Module 4): when you meet a new eval, read its scoring code the way you'd read a contract. The questions, in the order they pay off:

  1. What literally counts as success? Find the line that assigns the score. Not the README's description — the line of code.
  2. What happens to errors and non-answers? Dropped, counted as failures, or retried? Each choice biases differently.
  3. What's the exact prompt? Few-shot examples, formatting, system prompt. If they're not published, scores can't be reproduced — EleutherAI's first best-practice is "always share your exact prompts."[Eleuther]
  4. How is the answer extracted? Run the parser mentally against a correct answer phrased three different ways.
  5. How are scores aggregated? Micro or macro? Are repeated runs averaged? Are there error bars (Module 5)?
  6. Could a trivial system score well? The control-check question — see below.
Pitfall: the score that was too good

Anthropic once measured its models on BBQ, a bias benchmark, and got a bias score of zero — apparent perfection. A BBQ developer asked whether they'd run "a simple control to verify whether our models were answering questions at all. We found that they weren't."[Anthropic] The harness happily scored non-answers as unbiased. Before celebrating any metric, ask what a broken or trivial system would score on it — if the answer is "the same," the metric isn't measuring what you think.

Caveat

None of this means benchmark numbers are meaningless — it means a number is only interpretable together with its harness. "Model X scores 72.4 on ARC-Easy" is incomplete in the way "the trip takes three hours" is incomplete until you know by car or on foot. The fix is hygiene, not despair: pin the harness version, publish prompts and outputs, and never compare numbers across papers without checking the implementations match.[Eleuther]
