Module 7 · Tooling

The tooling landscape

Beyond Inspect sits an ecosystem of eval libraries, each encoding opinions about how evaluation should work. This survey reads four of them the way Module 4 read benchmarks — as artifacts whose design choices teach concepts — and ends with the trap the whole category invites.

OpenAI Evals: the first-generation blueprint

The 2023 OpenAI Evals framework deserves study as history: it codified the split every later tool inherited. Evals are declared, not coded — a YAML registry entry pointing at a JSONL dataset — and graded by one of two template families: basic templates, deterministic one-line predicates (Match, Includes, FuzzyMatch, JsonMatch — e.g. Includes is literally any([(b in a) for b in B])), and model-graded templates, where an LLM compares output to ideal answers — including a fact-checking rubric that returns a five-way classification (subset / superset / equal / disagreement / equivalent-modulo-style) rather than a bare score.[OpenAI Evals] The cookbook's guidance maps templates to question types: deterministic for closed-form answers, model-graded for open-ended[OpenAI Evals] — the grader hierarchy of page 3, stated in 2023. Status check (June 2026): the repo isn't archived but is in maintenance mode — housekeeping-only commits, custom-code contributions closed — and OpenAI's own cookbook recommends its hosted evals product instead.[OpenAI Evals]

promptfoo: the comparison matrix

promptfoo, an open-source CLI/library, organizes evaluation around a cross-product: "The YAML configuration format runs each prompt through a series of example inputs (aka 'test case') and checks if they meet requirements (aka 'assertions')" — and running multiple prompts against multiple providers yields "a matrix view" for side-by-side comparison.[promptfoo] Its assertion taxonomy is the most complete public catalogue of grader types, split into "Deterministic Eval Metrics" (string ops, JSON/SQL validation, custom code, latency and cost checks — Module 4's cost axis as an assertion — all negatable with a not- prefix) and "Model-Assisted Eval Metrics" (LLM rubrics, G-Eval, factuality, embeddings similarity, and four RAG metrics).[promptfoo] Two signs of where tooling is heading: trajectory assertions (trajectory:tool-used, trajectory:tool-sequence, trace-span checks) — process-based agent grading (page 11) as config — and first-class red-teaming, generating adversarial inputs (prompt injection and jailbreaking, treated as distinct attacks) and quantifying the risk.[promptfoo]

DeepEval: evals as unit tests

DeepEval frames LLM evaluation as software testing — native pytest integration, "run evals in CI/CD pipelines" — with a library of 50+ ready metrics.[DeepEval/Ragas] The load-bearing sentence in its docs: "almost all predefined metrics on deepeval uses LLM-as-a-judge."[DeepEval/Ragas] Those convenient metric names are judges, with everything Module 3 said about judges. The implementation details reward attention: its G-Eval doesn't just ask for a score — it uses chain-of-thought plus token-probability weighting, normalizing a 1–5 output into a probability-weighted 0–1 score.[DeepEval/Ragas] And a gotcha worth a pitfall box of its own: DeepEval's Hallucination and Faithfulness metrics are different computations with opposite polarity — Hallucination = contradicted contexts / total contexts (higher is worse); Faithfulness = truthful claims / total claims (higher is better).[DeepEval/Ragas]

Ragas: the RAG metric suite

Ragas popularized the four-metric decomposition of RAG quality, and the verified definitions show how much algorithm hides under each friendly name:[DeepEval/Ragas]

MetricQuestion it answersHow it's actually computed
FaithfulnessIs every claim in the answer grounded in the retrieved context?LLM extracts claims, verifies each against context; score = supported / total claims
Response relevancyDoes the answer address the question (regardless of truth)?LLM reverse-generates ~3 questions from the answer; score = mean embedding cosine similarity to the real question — embeddings, not a judge score
Context precisionDid the retriever rank relevant chunks high?Mean precision@k over the ranked retrieval list — a ranking metric, not hit/miss
Context recallWas everything needed actually retrieved?LLM splits a reference answer into claims; score = claims supported by retrieved context / total — requires ground truth, so not runnable on live traffic

(Naming note: current Ragas docs call the second metric "Response Relevancy" — class ResponseRelevancy — though "answer relevancy" persists across the ecosystem.) The deepest lesson in this table comes from comparing across tools: DeepEval's answer-relevancy counts relevant statements via a judge; Ragas's scores embedding similarity of reverse-engineered questions. Same metric name, different algorithm, different failure modes. A "relevancy: 0.85" means nothing until you know which computation produced it.

The category's trap

Pitfall: the metric menu

Fifty ready-made metrics invite a workflow this course spent Module 2 dismantling: pick plausible-sounding metrics from a menu, wire them into CI, and trust the dashboard. Recall the verified practitioner verdict on generic ready-to-use metrics — they "waste time and create false confidence," useful at most as exploration signals for surfacing traces, never as quality measures[Evals FAQ] — and that nearly every metric on these menus is an unvalidated LLM judge until you've measured its agreement with your domain expert (page 10). The tools are good engineering. The failure mode is using their menus as a substitute for error analysis rather than as implementations of evaluators your own data told you to build.

Key idea

Choose tools by reading their grader implementations, not their metric lists. The questions that differentiate this category: Which assertions are deterministic and which secretly call a judge? What does each named metric literally compute? Can it grade trajectories, or only final text? Does it preserve raw outputs for re-grading? Every tool on this page answers those differently — and the answers, not the feature matrices, determine what your scores will mean.
