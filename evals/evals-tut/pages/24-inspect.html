Module 7 · Tooling

Inspect: a harness in depth

This course's policy on tools: learn one deeply, survey the rest. The one is Inspect, the open-source eval framework from the UK AI Security Institute — chosen because its architecture is a clean implementation of everything Modules 1–6 taught, which makes its documentation double as a course in eval design.

The Task triad

Inspect's unit of evaluation is the Task — in the docs' words, "the fundamental unit of integration for datasets, solvers, and scorers" — built from exactly three components:[Inspect]

Task ├─ Dataset labelled samples — input (the prompt) + target │ (ideal answer, or grading guidance for a judge) ├─ Solver produces an answer per sample — a prompt chain, │ or a full agent with tools in a sandbox └─ Scorer evaluates the output — string comparison, model grading, or custom logic

Map it back to page 1's four-part machine and the correspondence is exact: dataset = data, solver = the system under test plus its harness plumbing, scorer = grader, and metrics aggregate scorer output. The framework makes the anatomy explicit instead of burying it in scripts — which is precisely what makes harness code auditable (page 2's checklist becomes "read three named components").

Solvers: from one prompt to a sandboxed agent

A solver can be a simple generation step — or an agent. Inspect ships react(), "a built-in agent that runs a reason-act-observe loop, giving the model the supplied tools until it submits an answer," with built-in tools spanning bash, Python, text editing, web search, web browsing, and computer use, plus custom and MCP tools.[Inspect] Because agents execute code, sandboxing is first-class: sandbox='docker' "runs all tool calls inside an isolated Docker container" configured by a Dockerfile or compose file alongside the task, with an extension API for Kubernetes, Modal, and other backends.[Inspect] Everything Module 4 said about environments-as-instruments lands here as configuration: the environment ships with the task, versioned, resettable per sample.

Custom scorers plug in through typed interfaces (Score, Target), and — a detail with real governance value — scores can be edited after the fact via edit_score(), preserving edit history and recomputing aggregate metrics automatically.[Inspect] That's the human-corrects-the-judge workflow of page 10 with provenance built in, instead of a spreadsheet nobody can audit later.

Epochs and reducers: Module 5, operationalized

Repeated trials aren't an afterthought: every Task takes an epochs option — "epochs to run for each dataset sample" — and reducers that aggregate the repeated scores: mean (the default), mode, or pass_at_k.[Inspect] That one option encodes the statistics module: K-resampling for variance reduction (page 16) and the pass@k estimator (page 18) as configuration rather than custom analysis code.

Eval logs as first-class artifacts

Where most homegrown harnesses print a number and discard the evidence, Inspect treats the log as the product. Runs write to a binary .eval format — "typically 1/8 the size of .json files," with incremental sample access so the interactive viewer (inspect view) stays fast at any file size — and a full log-file API supports streaming reads, header-only loads, and programmatic rescoring.[Inspect] Connect this to the reproducibility bundle from page 19: "always provide model outputs" stops being a discipline you maintain and becomes a side effect of running the tool. The log is the trace archive that error analysis needs.

Humans in the harness

Two human-in-the-loop features close loops this course opened. First, human baselining: the human_cli solver puts a person in the same sandboxed task the agent faces, with terminal sessions "recorded by default so that you can later view which actions the user took to complete the task."[Inspect] Remember OSWorld measuring its human ceiling at 72%, and METR's 2,529 hours of baselining — this is that methodology as a built-in: same environment, same scorer, human and model directly comparable. Second, approval policies: fine-grained rules for approving an agent's tool calls (--approval human, or custom approvers that approve, reject, or escalate)[Inspect] — supervised evaluation for agents too dangerous or expensive to run unattended.

Two precision notes

Attribution: Inspect is published by the UK AI Security Institute — the body renamed from "AI Safety Institute" in February 2025; older citations use the old name. And a scoping note: Inspect provides human baselining and human approval; it does not ship a built-in judge-vs-human agreement workflow — the TPR/TNR validation of page 10 is still yours to run (the log API gives you the data to do it).

Key idea

Inspect is this course expressed as software: the four-part machine as a named triad, graders as a typed spectrum, repeated trials and pass@k as configuration, logs as durable evidence, humans as first-class participants. Learning it deeply isn't tool trivia — it's rehearsing the concepts until they're muscle memory. The next page surveys the rest of the ecosystem against this baseline.
