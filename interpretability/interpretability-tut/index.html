Interpretability Methods and Rigor

How to make a claim about a model’s internals that survives a test written before you looked: the methods, the controls, and two replications you can run on a laptop.

The professional target

Given a claim about what a neuron, direction, head, or feature does, write the test that would show it on data not yet seen, with the control that would pass if the claim were empty, then run it and report the result either way.

Start with what “demonstrated” means →

What you will be able to do

  • Turn an interpretability claim into a pre-registered prediction test with held-out data, a scoring function, controls, and a threshold.
  • Explain why max-activating examples mislead and sample activations so they do not.
  • Score an explanation by held-out activation prediction and read the random-unit and shuffled-label controls.
  • Replicate a vision-neuron claim on InceptionV1 and a language claim on GPT-2 small on a CPU, with the test written first.
  • Use probes, the logit lens, activation patching, and induction-head detection, and say what each does and does not establish.
  • Read a sparse-autoencoder feature’s explanation and its score, and write up a result, including a negative one, so that it is a contribution.

How to work through it

This is the capstone of the evals-and-interpretability path. It assumes the Python for Model Internals, Linear Algebra for Interpretability, and Transformer Anatomy courses, and it leans on the statistics and evals courses for controls, multiple comparisons, and held-out validation. Each lesson has a worked mechanism, a pitfall, a check with a revealable explanation, and practice. Where a lesson runs code, the output shown was produced on the authoring machine and is kept verbatim in the transcript; replications that failed are reported as failed.

Practice locally

Reading needs no server or packages. The labs need a Python environment with torch (CPU is enough), torchvision, transformers, transformer_lens 4, and numpy, with GPT-2 small and torchvision’s GoogLeNet weights cached. From this directory:

python labs/reference/curve_tuning.py
python labs/reference/neuron_score.py --rule digit
python -m unittest discover -s labs -p 'test_*.py'

In every command on these pages, python means the interpreter of that environment. The learner labs in labs/ are stubs with tests; the reference implementations in labs/reference/ produced the outputs shown and are there to read after you have tried. The protocol template and the command reference are the two pages to keep open.

Sources and scope

Original explanations are supported by the annotated bibliography, which records what was checked in each source. The 2026 essay by Nick Cammarata and the reply by Leo Gao were fetched and are quoted verbatim where used. Experiments use torchvision’s GoogLeNet weights and GPT-2 small; neither is the model the cited papers studied, and the lessons say so wherever it matters.
