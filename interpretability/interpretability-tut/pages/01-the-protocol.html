Module 0 · Claims and the protocol

The protocol: write the test before you look

The pre-registration template, field by field, and the lab that refuses to run until it is filled in.

The order of operations

The protocol is one rule with consequences: decide how you will judge the claim before you see the evidence that will judge it. Written out, it has eight fields, and Appendix A keeps a copy. The lab labs/protocol.py encodes it as a Preregistration record whose run() raises ProtocolError if any field is blank or still says “TODO”, and whose judge() returns “demonstrated” only when the score meets the threshold and beats every control’s 95th percentile.

CLAIM        one falsifiable sentence
UNIT         model, layer, hook point, index, and how it was chosen
HELD-OUT     the data the score is computed on, untouched by the choosing
SCORING      the function from claim and data to a number
PREDICTION   the number, as an inequality
THRESHOLD    the pass line, fixed now, justified by the control
CONTROLS     at least two; for each, what passing would mean
FAILURE      what you will write if it fails
LOOKED?      whether you have already seen the held-out data

Each field, and the way it goes wrong

Claim. “Related to punctuation” cannot fail. “Fires on sentence-final punctuation and not on commas” can. Write the one that can.

Unit and how it was chosen. If you searched 36,864 neurons for the one that best fits your rule, say so, because the search is where selection bias enters. The best of thirty-six thousand random correlations is not small. In lesson 04 the screening split absorbs that bias and the held-out split measures what is left.

Held-out. Data that played no part in forming or choosing the claim. Not “other examples I also looked at.” The cleanest version is a split made before the investigation started, as the labs do with alternating 128-token chunks of the corpus. For vision (lesson 06) the held-out data are stimuli rendered with parameters the screening never used.

Scoring. One function, named. Correlation between the rule’s predictions and the activations; F1 of the rule as a classifier of “fires”; recovered fraction of a logit difference; prefix-matching score. Each measures something different (lesson 04 compares them). Pick before you run, because after you run you will know which one looks best.

Prediction and threshold. A number and a line. The line should be justified by what the control is expected to reach, with margin, not by what you hope the unit reaches. Lesson 08 shows a threshold that was badly chosen in exactly this way, and the test failed because of it. That failure is reported as a failure.

Controls. A control is a comparison that would also pass if the claim were empty. Random unit, shuffled labels, baseline explanation, rotated stimulus, unrelated position. Lesson 05 is about what each one rules out. Two is the minimum because they rule out different things.

Failure. Write the sentence now: “If r on held-out tokens is below 0.5, the rule is not a demonstrated explanation of this neuron, and we report r and both control percentiles.” Writing it now makes it much harder not to write it later.

Looked? Honesty field. If you have already decoded the held-out chunks and seen where the neuron fires, the test is a post-hoc fit. It can still be informative; it is not a pre-registration.

The protocol as code

from protocol import Preregistration, run, ProtocolError

p = Preregistration(
    claim='L2/2928 fires on the first token of a sentence',
    unit='gpt2 blocks.2.mlp.hook_post[:, 2928], chosen by screening on even chunks',
    heldout_data='odd 128-token chunks of labs/data/corpus.txt',
    scoring='Pearson r between rule indicator and activation',
    prediction='r >= 0.5', threshold=0.5,
    controls=['random_unit', 'shuffled_labels'],
    failure_means='not a demonstrated explanation; report r and control percentiles')

result = run(p, experiment)   # experiment() returns (score, {control: scores})
print(result['verdict'])      # 'demonstrated' or 'not demonstrated'

The tests in labs/test_protocol.py check that an incomplete protocol is refused before the experiment function is even called, that the pre-registered controls must actually be reported, and that a control scoring as high as the claim defeats it even above threshold. Make them pass before lesson 04.

In interpretability work

Cammarata’s essay describes a test of this shape done at scale: for twenty Qwen3-32B neurons, “Reading only a neuron’s explanation, an agent wrote five new examples that should drive it and five near misses that shouldn’t,” and calls positive controls “one of many tools for criticizing an explanation of a neuron” [Cammarata 2026]. The structure is the protocol: predictions from the explanation alone, on inputs not yet seen. What the essay and Gao disagree about is whether that structure, applied to strong examples, is enough.

Pitfall

Pre-registering after a pilot on the same data. If you ran the rule on the held-out chunks “just to see,” then wrote the threshold, the chunks are no longer held out. Split again, or report it as exploratory.

Check your understanding

You screened 500 candidate units for the one most correlated with “token is a digit” and found r = 0.97 on the screening data. A teammate says the held-out test is a formality since 0.97 cannot be luck. Is it?

Reveal the reasoning

The held-out test is not a formality, but not mainly because 0.97 could be luck on 500 draws (it cannot, at that sample size). It is because the screening score is the maximum over a search, so it is biased upward by an amount you do not know, and because the controls have not been run: the held-out test is also where you learn what a random unit scores against the same rule, and whether the rule’s score survives the shift to new text. Report the held-out number, not the screening one.

Practice

Implement labs/protocol.py until its tests pass. Then fill in a protocol for a claim of your own about any GPT-2 neuron you have not yet looked at, and keep it for the capstone.

python -m unittest discover -s labs -p 'test_protocol.py' -v
What to look for

The hardest test is usually the one that checks judge() against a control whose 95th percentile is above the score: your implementation must compare against the percentile, not the mean and not the single maximum. The protocol is only as strict as its weakest control.
