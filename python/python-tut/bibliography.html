Sources and provenance

Annotated bibliography

Official documentation pages checked for the specific behaviours the lessons quote.

These pages were opened and checked during authoring on 2026-10-20. The notes identify the scope verified; they do not claim that an entire source was independently reproduced. Where a page did not state something the course relies on, the local transcript is the evidence and the note says so.

Python: data model

Python 3 Language Reference, §3.1 Objects, values and types

Verified: every object has an identity, a type and a value; identity and type never change; mutability is determined by type (numbers, strings and tuples immutable; dictionaries and lists mutable).

Python: json

Python 3 Library Reference: json

Verified: duplicate names in a JSON object are accepted and only the last value is kept by default; object_pairs_hook receives the ordered list of pairs and can change that; JSONDecodeError is a ValueError subclass with lineno and colno; null/true/false map to None/True/False.

Python: unittest

Python 3 Library Reference: unittest

Verified: python -m unittest discover with -s (start directory) and -p (file pattern); subTest() context manager labels parameterised cases; assertRaises used as a context manager stores the exception in .exception.

Python: dataclasses

Python 3 Library Reference: dataclasses

Verified: @dataclass generates __init__, __repr__ and __eq__ (field-by-field, same type required); frozen=True raises FrozenInstanceError on assignment; an unhashable default such as a list raises ValueError, and field(default_factory=list) is the supported alternative.

NumPy: broadcasting

NumPy user guide: Broadcasting, General broadcasting rules

Verified: shapes are compared element-wise starting from the trailing dimension; two dimensions are compatible when they are equal or one of them is 1; otherwise ValueError: operands could not be broadcast together.

NumPy: einsum

NumPy reference: numpy.einsum

Verified: a repeated subscript label is summed; a label appearing once is kept; explicit mode uses "->" to name the output axes and can force or disable summation; "ii" is the trace and "ii->i" the diagonal; "ij,j" is a matrix-vector product.

PyTorch: broadcasting

PyTorch notes: Broadcasting semantics

Verified: iterating from the trailing dimension, sizes must be equal, one of them 1, or one of them missing; missing leading dimensions are treated as 1 and each result dimension is the max of the two; an in-place operation may not change the in-place tensor's shape as a result of the broadcast.

PyTorch: views

PyTorch docs: Tensor Views

Verified: a view shares the underlying data with its base tensor, so writing through it changes the base; view(), transpose(), permute(), squeeze() and basic slicing return views; a view of a contiguous tensor can be non-contiguous; reshape() may return either a view or a copy; contiguous() returns itself when already contiguous.

PyTorch: autograd

PyTorch notes: Autograd mechanics

Verified: an operation is recorded only if at least one input requires grad; only leaf tensors with requires_grad=True accumulate .grad; no-grad mode makes computations behave as if no input requires grad and is for operations that should not be recorded; in-place operations are discouraged and can overwrite values needed for gradients, with a version counter raising an error when that happens.

PyTorch: nn.Module

PyTorch reference: torch.nn.Module (register_forward_hook, state_dict, named_parameters)

Verified: a forward hook has signature hook(module, args, output) -> None or modified output, runs every time after forward() has computed an output, can modify the output, and returns a RemovableHandle whose remove() unregisters it; with_kwargs and always_call options; state_dict() returns a shallow copy with references to parameters and persistent buffers; named_parameters() yields (name, Parameter) pairs.

PyTorch: randomness

PyTorch notes: Reproducibility

Verified: torch.manual_seed seeds the RNG for all devices; completely reproducible results are not guaranteed across PyTorch releases, commits or platforms; torch.use_deterministic_algorithms selects deterministic algorithms where available.

Transformers: outputs

Transformers documentation: Model outputs (ModelOutput)

Verified: outputs are ModelOutput dataclasses usable by attribute, key or index, with None attributes skipped when treated as a tuple; hidden_states is returned only when output_hidden_states=True, as a tuple with one tensor for the embedding output plus one per layer, each (batch_size, sequence_length, hidden_size); hidden_states[-1] need not equal last_hidden_state for every model because some apply normalisation.

Transformers: GPT-2

Transformers documentation: GPT-2 (GPT2Config, GPT2LMHeadModel.forward)

Verified: GPT2Config defaults vocab_size 50257, n_positions 1024, n_embd 768, n_layer 12, n_head 12; GPT2LMHeadModel.forward returns logits of shape (batch_size, sequence_length, config.vocab_size) and optional hidden_states (embedding output plus one per layer, each (batch_size, sequence_length, hidden_size)) and attentions (one per layer, (batch_size, num_heads, sequence_length, sequence_length)).

TransformerLens: migrating to 4.0

TransformerLens documentation: Migrating to TransformerLens 4.0

Verified: 4.0 removes the legacy Hooked* model stack; HookedTransformer is replaced by TransformerBridge.boot_transformers(name) plus enable_compatibility_mode(); compatibility mode reproduces HookedTransformer's default weight processing (LayerNorm folding, center_writing_weights, center_unembed) verified against frozen reference activations; without it the bridge uses raw Hugging Face weights, the equivalent of the old from_pretrained_no_processing. The page does not itself state that blocks.N.hook_resid_post names keep working; that is verified locally in the transcript.

TransformerLens: releases

TransformerLens GitHub releases (v4.0.0, v4.1.0, v4.2.0)

Verified: v4.0.0 lists the Hooked class deprecation and final deprecation preparation, bridge migration recipes and a one-time converter for legacy TL-format checkpoints; v4.1.0 fixes gradients in compatibility mode for left-padded batches. The installed version during authoring was 4.2.0.

nnsight: getting activations

nnsight documentation: Getting activations

Verified: open a tracing context with model.trace(...), read a module's forward-pass return value with .output, mark values with .save() to bring them back under the bound name; a traced with block does not run in place and saved activations are real tensors usable after the context exits. The examples use TransformersModel; LanguageModel, used here, is its subclass in nnsight 0.8.1.

nnsight: tracer

nnsight documentation: Tracing, Tracer

Verified: the body of a trace block is captured and run through the backend rather than executed inline; save marks a value to be returned to the user after the outermost trace; derived values need their own .save().

safetensors

Hugging Face documentation: Safetensors

Verified: a simple format for storing tensors safely, as opposed to pickle, and still fast (zero-copy); save_file(dict_of_tensors, path) and safe_open(..., framework="pt") with get_tensor(key) are the basic torch API.
