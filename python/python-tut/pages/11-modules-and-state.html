Module 3 · Models as objects

nn.Module, parameters, state_dict, and reading a module tree

A model is a tree of modules, each with named parameters and a forward method. Learn to read the tree and the rest of the toolkit becomes navigation.

What a module is

nn.Module is a class with three jobs: it owns parameters, it owns child modules, and it defines forward. Assigning an nn.Linear to self.up inside __init__ registers it as a child; the parent then finds the child's parameters through parameters(), saves them through state_dict(), and moves them with .to(device). Calling the module, mlp(x), runs forward plus the bookkeeping that fires hooks, which is why you call the module and never forward directly.

Read the tiny MLP

Printing a module prints its tree, with each leaf's constructor arguments. named_parameters() yields (name, Parameter) pairs [PyTorch: nn.Module], and the names are dotted paths through the tree: up.weight, down.bias. The shapes carry a convention worth memorising: nn.Linear(8, 32).weight is (32, 8), stored as (out_features, in_features), so the forward computes x @ W.T + b. GPT-2's Conv1D layers below use the opposite convention, (in, out), which is a historical quirk you will meet when reading its weights in the transformer course.

state_dict() returns a dictionary from those same names to tensors, containing parameters and persistent buffers; the documentation notes it is a shallow copy holding references to the module's tensors [PyTorch: nn.Module], so editing a value in it edits the model. Saving a model is saving this dict; loading is load_state_dict. 552 parameters for the tiny MLP is 8·32 + 32 + 32·8 + 8; count it once by hand so you trust numel().

Read GPT-2 small's tree

The top level has two children: transformer, the stack, and lm_head, the unembedding. Inside transformer: wte, the token embedding of shape (50257, 768); wpe, the position embedding, (1024, 768), which is why the context limit is 1024; drop, a dropout that does nothing in eval mode but is a convenient place to hook the embedding output; h, a ModuleList of 12 GPT2Blocks; and ln_f, the final LayerNorm. Each block is ln_1, attn, ln_2, mlp: normalise, attend, normalise, feed forward, with the residual additions in the block's forward.

The parameter count, 124,439,808, is the "124M" in the model's name. The lm_head.weight shares storage with wte.weight: the same data_ptr(), as the output shows. Tied embeddings mean the state_dict has 149 entries while named_parameters() lists one tensor fewer by default, because it removes duplicates. model.training is False after .eval(); forgetting that call leaves dropout active and makes two forward passes disagree.

get_submodule("transformer.h.5.mlp") walks a dotted path to a module. That string is the address you give to a hook, and it is the same path that appears in state_dict keys with .weight appended. TransformerLens renames these addresses (blocks.5.mlp) and nnsight keeps them; lesson 14 has the table.

Navigating any model

Four calls answer most questions about an unfamiliar model. print(model) for the tree. [n for n, _ in model.named_children()] for one level. {n: tuple(p.shape) for n, p in model.named_parameters()} for every shape. model.config for the hyperparameters a Hugging Face model was built from; n_layer, n_embd and n_head for GPT-2 are 12, 768 and 12 [Transformers: GPT-2]. The sum of parameter sizes should match the published count, and if it does not you have the wrong checkpoint.

In eval and interpretability work

"Layer 5" is ambiguous until you say which module: transformer.h.5 is the block, transformer.h.5.mlp its MLP, and transformer.h.5.attn.c_proj the attention output projection. Write the dotted path in your notes, not the number.

Pitfall

Loading a model and not calling .eval(). Dropout stays on, activations change between runs, and a cache you compare against a later run differs by noise you then try to explain.

Check your understanding

Someone says GPT-2 small has "about 85M non-embedding parameters". From the tree above, how would you check that in two lines?

Reveal the reasoning

Sum p.numel() over named_parameters() whose name does not start with transformer.wte or transformer.wpe. The embeddings are 50257·768 plus 1024·768, about 39.4M, so the remainder of 124.4M is about 85M. The check is a comprehension over names, which is why names matter.

What to look for

Filter named_parameters() by prefix f"transformer.h.{i}." and strip the prefix. Twelve identical dicts; c_attn.weight is (768, 2304), three times 768 because queries, keys and values are produced by one matrix and split. That split is a reshape you will write in the transformer course.
