Module 3 · Models as objects

Loading GPT-2 small: tokenizer, input ids, logits, next token, hidden states

One forward pass, read by shape at every step: text to ids, ids to logits, logits to a prediction, and the thirteen hidden states in between.

Load once, in eval mode

AutoTokenizer.from_pretrained("gpt2") and AutoModelForCausalLM.from_pretrained("gpt2") read the cached files. The model is a GPT2LMHeadModel, the tree from lesson 11. Call .eval(). Loading takes a few seconds and should happen once per script or once per test class, never per prompt.

Text becomes ids of shape (batch, seq)

The tokenizer returns a dict with input_ids and attention_mask; return_tensors="pt" makes them torch tensors with a batch axis of 1. Five tokens for five words here, but the tokens are 'The', 'Ġcapital', ...: GPT-2's byte-pair encoding attaches the leading space to the word, and the Ġ is how it displays that space. A word you did not expect to split will split, and a space before the prompt changes the first token. Token counts are not word counts, and the seq axis counts tokens.

Logits are (batch, seq, vocab)

The model returns a ModelOutput dataclass; out.logits has shape (batch_size, sequence_length, config.vocab_size), the scores for every vocabulary item at every position before a softmax [Transformers: GPT-2]. Position i holds the prediction for the token after position i, so the prediction for what follows the prompt is out.logits[0, -1], shape (50257,). softmax(-1) turns it into probabilities and topk reads off the best five: ' the' at 8.5%, with ' Paris' fifth at 3.2%. GPT-2 small is a weak model; that is fine, and it is also why the sentence is a useful test prompt: the right answer is present but not dominant, so an intervention that changes it is visible.

Thirteen hidden states of (batch, seq, 768)

output_hidden_states=True adds out.hidden_states: a tuple with one tensor for the output of the embeddings plus one for the output of each layer, each of shape (batch_size, sequence_length, hidden_size) [Transformers: outputs]. Twelve layers plus the embedding is thirteen, and hidden_size is 768. The indexing convention is the one to get right once: hidden_states[0] is the embedding output, before any block; hidden_states[i + 1] is the residual stream after block i; so "after block 5" is index 6.

The last entry has a wrinkle. The documentation warns that hidden_states[-1] need not equal the last hidden state exactly because some models apply normalisation to it [Transformers: outputs], and GPT-2 is one of them: hidden_states[12] is the output of ln_f, not the raw output of block 11. Lesson 13 shows the difference directly with a hook. If you want the residual stream after the last block, hook the block.

The norms across layers grow from about 5 at the embedding to several hundred by the last block, then drop after ln_f. That growth is a known feature of GPT-2's residual stream and is why comparisons across layers normalise first; the linear-algebra course takes this up.

Batching needs a pad token and a mask

GPT-2 ships with no pad token, as the None shows. Assigning tokenizer.pad_token = tokenizer.eos_token is the standard fix. A batch of two prompts of different lengths is padded to the longer, here on the right, and the attention_mask marks real tokens with 1 and padding with 0. Passing the mask makes attention ignore the padding; the output confirms the first prompt's activations are unchanged by batching to 1e-4. The padded positions of the shorter prompt still produce numbers, and they are garbage: every reduction over the sequence axis must use the mask, which is what masked_mean_pool in the shape lab is for.

In eval and interpretability work

A next-token eval is logits[:, -1].argmax(-1) compared with a reference id, for a batch. Everything that can go wrong is a shape or tokenisation question: did you take the last real token or the last padded one, and is the reference a single token in this tokenizer.

Pitfall

Off by one on layers. "Layer 6 activations" might mean hidden_states[6] (after block 5) or the output of block 6 (hidden_states[7]). State the block index and the convention in every file name and manifest; the readiness review asks for it.

Check your understanding

You batch ten prompts, pad on the right, and compute out.logits[:, -1] to score each prompt's next token. Which prompts are scored correctly?

Reveal the reasoning

Only the longest ones. For a shorter prompt, position -1 is a padding token and its logits predict what follows padding. Either pad on the left so the last real token is at -1, or index each row at attention_mask.sum(-1) - 1. The mask tells you where the real end is; use it.

What to look for

The context makes " Berlin" likely; GPT-2 small does in-context pattern completion even at 124M. The leading space changes the first token from The to ĠThe, a different id, which is why prompt formatting is part of an eval's specification.
