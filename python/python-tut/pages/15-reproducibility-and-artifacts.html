Module 3 · Models as objects

Reproducibility and artifacts: seeds, safetensors, a run manifest, memory and batching on CPU

An activation file is a claim: these prompts, this model, this convention produced these numbers. The manifest is what lets someone else check it.

Seeds, and what they do not promise

torch.manual_seed(n) seeds the generator for all devices [PyTorch: randomness]; the script shows two randn calls after the same seed producing the same numbers. NumPy has its own generator, seeded separately, and np.random.default_rng(n) is the modern form. Seed both at the top of anything that samples. What seeds do not promise is agreement across machines: the documentation says completely reproducible results are not guaranteed across PyTorch releases, individual commits, or platforms [PyTorch: randomness]. On one machine with one version, the output shows a repeated GPT-2 forward pass is bit-identical; across machines expect float32 noise, and write your comparisons with allclose and a tolerance you state.

$ python3 labs/examples/reproducibility.py
same seed, same draw: True [1.5409960746765137, -0.293428897857666, -2.1787893772125244]
numpy has its own generator: [0.126, -0.132]
stacked hidden states: (13, 2, 5, 768) | 0.40 MB in float32
a 1024-token prompt would need 41 MB for the same stack; a batch of 32 of them 1.3 GB
repeat forward pass identical: True
safetensors round trip: 13 tensors, 0.40 MB, block.5 equal: True
manifest keys: ['attention_mask', 'model', 'prompts', 'seed', 'tensors', 'versions'] | block.5 entry: {'shape': [2, 5, 768], 'dtype': 'float32', 'sha256': 'b5d58813c4d9d650...'}

Memory arithmetic you should do in your head

A float32 is 4 bytes. Thirteen hidden states of (2, 5, 768) is 13·2·5·768·4, 0.40 MB, matching the output. The same stack for a 1024-token prompt is 41 MB; a batch of 32 of them is 1.3 GB, which is where a laptop starts swapping. The rules that follow: cache only the layers you need, not all thirteen; keep no_grad on so no graph is held; process prompts in batches and write each batch to disk before the next; and store in float16 only when you have checked the precision loss is acceptable for the comparison you will make. Model weights are 124M parameters times 4 bytes, about 500 MB, loaded once.

Batching trades memory for speed and introduces padding. Pad with the EOS token, pass the attention mask, and record the mask in the manifest, as the script does, so that whoever reads the file knows which positions are real. Prompts of very different lengths waste compute on padding; sort by length and batch neighbours.

safetensors over pickle

torch.save pickles, and pickle executes code on load. The safetensors format stores tensors safely, as opposed to pickle, and is still fast with zero-copy loading [safetensors]; save_file(dict_of_tensors, path) and load_file are the whole API for the common case. It requires contiguous tensors, hence the .contiguous() calls, and it is the format the gpt2 checkpoint itself uses in your cache. The 0.40 MB file round-trips with torch.equal true. Use it for anything you share; use torch.save for a scratch file you will delete.

The run manifest

A manifest is a small JSON file beside the tensors answering the questions lesson 14 raised. The script writes six keys: the model name, the prompts in order, the seed, the library versions, the attention mask, and for every tensor its shape, dtype and a checksum of its bytes. With sorted keys and no timestamps, the same run produces the same file, which means diff can tell you whether two runs agree before you load a single tensor. The manifest.py lab asks for this as four functions, with tests that check the checksum is stable across a non-contiguous view and that every kind of mismatch is reported rather than raised.

Add to that list anything that changed the numbers in lesson 14: whether a BOS token was prepended, whether compatibility mode was on, and which layer convention the keys use. A manifest that says block.5 means "output of transformer.h.5, before ln_f" has answered the off-by-one question for everyone downstream.

Habits that make artifacts checkable

Name files by content, not by date: gpt2_resid_post_blocks0-11_fp32.safetensors. Keep the script that produced an artifact next to it, and make the script idempotent so re-running it overwrites rather than appends. Put a check_manifest call at the start of any script that consumes the file, so a stale or truncated file fails fast. And record the command line and the environment, which is what scripts/verify_commands.py does for this course's own outputs: the transcript at the top of each lesson's output is the same discipline applied to the course itself.

In eval and interpretability work

Every claim in the interpretability course will be of the form "on these activations, this prediction held". The activations are an artifact with a manifest, or the claim cannot be checked by anyone, including you in three weeks.

Pitfall

Saving activations in float16 to halve the file and then testing a direction with a tolerance of 1e-5. float16 has about three significant digits; the comparison is meaningless. Decide the precision from the test you will run, and write it in the manifest.

Check your understanding

Two manifests from two machines agree on every shape and dtype and disagree on every checksum. The argmax tokens agree. What do you conclude and what do you do?

Reveal the reasoning

Float32 non-determinism across platforms, which the reproducibility notes say to expect: the bytes differ at the last digits and the checksums are hashes of bytes. Confirm by loading both files and checking allclose with a stated tolerance, then record that tolerance and both version strings in a comparison note. Do not "fix" it by regenerating until the hashes match; they will not.

Practice

Implement labs/manifest.py and make its tests green. Then extend a copy of reproducibility.py to call your build_manifest and check_manifest on the safetensors round trip, and deliberately corrupt one value before checking.

$ python3 -m unittest discover -s labs -p 'test_manifest.py' 2>&1 | tail -1
FAILED (errors=10)
What to look for

The digest test with a transposed view forces np.ascontiguousarray before hashing. check_manifest must return strings, not raise, so a consumer can report all problems at once. A single changed value changes the digest, and your check names the tensor.
