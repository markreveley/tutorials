Module 1 · Python for someone coming from Elixir and Rust

Functions, generators, dataclasses, and type hints as documentation

The idioms you will read in every toolkit: keyword arguments, lazy iteration, records as classes, and hints that document without enforcing.

Functions and the calling conventions you will read

Python functions take positional and keyword arguments, and most library calls you will read use keywords for anything optional: model(**enc, output_hidden_states=True). The **enc unpacks a dict into keyword arguments, so a tokenizer's output dict with input_ids and attention_mask becomes two named arguments. *args collects extra positionals into a tuple and **kwargs extra keywords into a dict; a forward hook's signature, hook(module, args, output), receives the module's positional inputs as that tuple.

Functions are objects. You pass them to register_forward_hook, store them in dicts, and return them from other functions, which is how lesson 13 builds one hook per layer with a closure: make_hook(name) returns a function that remembers name. A lambda is a one-expression anonymous function; fine for a sort key, cramped for a hook.

Generators: a Stream without the module

A function containing yield returns a generator object when called and runs nothing until something asks for a value. read_jsonl above opened no file at the call; next(rows) read one line. The rest were consumed by a comprehension, and after that the generator is exhausted: list() of the same generator object would be empty, which is why the script calls read_jsonl(path) again. If you know Elixir's Stream or Rust's iterators, the mental model is the same: lazy, single-pass, and composable with for, sum, any, and comprehensions.

The generator expression (n * n for n in range(4)) is the inline form. The million-term sum builds no list. Use generators for files larger than memory and for activations you want to process one batch at a time; use lists when you need to index, take len, or iterate twice.

Dataclasses: records with a generated constructor

@dataclass reads the annotated fields and generates __init__, __repr__, and a field-by-field __eq__ [Python: dataclasses]. The printed Result(...) is the generated repr; the equality line is the generated __eq__. frozen=True makes assignment raise FrozenInstanceError, which is as close to an Elixir struct as Python gets, and the right default for records that go into a log.

The Run class shows the module refusing a list default, by design: a mutable default would be shared across instances, the trap from lesson 02. field(default_factory=list) calls list() per instance, and the output shows the two runs with separate lists. Hugging Face's ModelOutput classes are dataclasses too, which is why out.logits and out.hidden_states are attributes with generated reprs.

Type hints document; they do not check

def accuracy(passed: int, scored: int) -> float | None tells a reader what to pass and what comes back. It tells the interpreter nothing. The last lines show accuracy("3", "4") failing only because / refuses strings, not because the hint said int. Tools such as mypy or pyright check hints statically if you run them; this course does not require them, but writing hints on every function you share is the cheapest documentation there is, and list[str], dict[str, float], and X | None cover most of what you need. For tensors, a hint cannot express a shape, which is why the convention is a comment: # (batch, seq, d_model) next to the parameter. Treat that comment as part of the signature.

Context managers

with open(path) as f: closes the file when the block exits, even on an exception. with torch.no_grad(): turns gradient recording off for the block. with model.trace(prompt): in nnsight captures a block of code to run against a forward pass. The protocol is two methods, __enter__ and __exit__, and contextlib.contextmanager lets you write one from a generator with a single yield, which is the neatest way to write "register these hooks, run this, remove them no matter what" in lesson 13.

In eval and interpretability work

A frozen dataclass for a terminal result, with status and either passed or error, makes the invalid states in summarize_run's tests, such as an error row that also carries passed, impossible to construct by accident. Validate once at the boundary, then trust the type.

Pitfall

Iterating a generator twice. The second loop is silently empty, and a metric computed over it is zero over zero. If a function might be called on a generator, convert with list() at the entry or document that it consumes its input.

Check your understanding

A colleague annotates a function def cache(acts: torch.Tensor) -> torch.Tensor and it is called with a tuple of tensors from a hook. Nothing warns. What happens, and what should the signature have said?

Reveal the reasoning

Nothing warns because hints are not enforced; the function proceeds until some tensor method is called on a tuple and raises AttributeError several lines later. GPT-2 block outputs in this transformers version are tensors, but other modules return tuples, so the hint should admit the possibility or the hook should normalise with output[0] if isinstance(output, tuple) else output first, which lesson 13 does.

What to look for

Duplicate detection needs state across yields, a set of seen ids kept inside the generator, which is fine because a generator keeps its locals alive between yields. The line-number message comes from the same enumerate(f, start=1), and the exception propagates out of list() unchanged.
