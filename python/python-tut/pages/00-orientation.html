Module 0 · Orientation and setup

What this course makes you able to do

Enough Python and PyTorch to load a small model, read its activations by shape, and test what you built, written for someone who already programs for a living.

The job is to be fluent, not clever

Every interpretability toolkit is Python: the model loaders, the hook APIs, the notebooks that papers ship, the eval harnesses. If you have worked with Elixir and Rust code, even mostly by generating and reading it, Python's concepts will be familiar. What slows people down is different: Python has no compiler to tell you a shape is wrong, so a (batch, seq, d_model) tensor that silently became (seq, d_model) produces a plausible number instead of an error. Syntax takes weeks. Being able to say, before you run a line, what shape comes out of it takes months, and that is the skill this course is built around.

The target is concrete. At the end you will load GPT-2 small, capture the residual stream after every one of its twelve blocks with forward hooks, assert that every captured tensor is (batch, seq, 768), save the activations with a manifest someone else can check, and have the eval-pipeline labs green. That is the readiness test the roadmap names for the first barrier, and it is what the readiness review asks of you.

Python habits → arrays and shapes → tensors and autograd → modules and hooks → activations you can test and save

Four modules and a review

Module 1 teaches Python by contrast with the Elixir and Rust you have seen. Names bind to objects and mutation is visible through every alias, which is the opposite of the BEAM's immutability and of Rust's ownership. Exceptions are the error channel, not {:ok, _} or Result. The practice is the three eval-pipeline functions that already ship with tests: score_ticket, load_cases, summarize_run. You will write them spec-first, which is the habit you already have.

Module 2 is the spine. NumPy arrays and their shapes, broadcasting as a rule you can apply by hand, reductions over named axes, einsum strings read aloud, then the same ideas in torch with dtypes, devices, views, in-place operations, and autograd. There is a shape-prediction drill and a lab whose tests are shape assertions.

Module 3 treats models as objects. nn.Module trees, parameters and state_dict, GPT-2 small through transformers, forward hooks, and then the same activation captured three ways: a raw hook, TransformerLens 4, and nnsight. You will see which numbers agree, which differ, and why. The module ends with seeds, safetensors, a run manifest, and what fits in CPU memory.

The review is a rubric, not a quiz. It lists the abilities and which lesson to revisit if one is missing.

Three professional abilities

  • Read: open a notebook from a paper and know, line by line, what shape each tensor has and whether a name is an alias or a copy.
  • Build: write a function from its test, capture an activation with a hook, and remove the hook afterwards even when the forward pass raises.
  • Check: assert every shape, keep autograd out of inference code, and leave a manifest that lets a colleague verify the file you produced.

How to read the lessons

Each lesson has the same parts: a mechanism shown in a small script, a terminal block with the real output of that script, a pitfall, a judgment question with a revealable explanation, and practice with an answer. The terminal blocks are not illustrations. Every command was executed by scripts/verify_commands.py and the output next to it is what came back, with versions recorded in the transcript. If your output differs, the difference is information: a version, a platform, or a mistake, and the lesson on reproducibility will tell you which.

Predict before you reveal. When a lesson prints a shape, cover it and say the shape first. When it shows an error, say which line raises. The miss is the lesson.

The scripts live in labs/examples/ and are short enough to read in full. Run them from the course directory, tutorials/python/python-tut, after the setup in lesson 01. Here is the one you will run first:

$ python3 labs/examples/check_setup.py
python 3.13.16
numpy 2.5.4
torch 2.14.1+cpu | cuda available: False
transformers 5.20.2
a batch of 2 prompts, 5 tokens each, 768 numbers per token: (2, 5, 768)
x.shape[0] is the batch: 2 | x.shape[-1] is d_model: 768

Three numbers there will follow you through the course: a batch of 2, a sequence of 5 tokens, and 768 features per token, which is GPT-2 small's d_model. You will see (2, 5, 768) so often that reading it as "two prompts, five positions, one vector each" should become automatic.

In eval and interpretability work

Most bugs that cost a week are not algorithmic. They are a hook left registered, a tensor that still carries a gradient graph into a cache, a batch dimension dropped by an index, or a padded position averaged into a mean. All four are shape and object-identity mistakes, and all four are caught by the habits this course drills.

Pitfall

Treating Python as "Rust without types" and skipping the fundamentals because the syntax looks easy. The semantics of names, mutation and views are where the surprises are, and they bite hardest inside a 200-line notebook you did not write.

Check your understanding

A colleague says their activation cache is "about 100 MB" and the saved file is 2 GB. Before reading any code, what are your first two hypotheses?

Reveal the reasoning

Either the cached tensors still carry autograd graphs and were saved with them, or every batch was captured with a hook that was never removed, so later forward passes appended more. Both are object-lifetime mistakes, not arithmetic ones. Lesson 13 shows the second directly and lesson 15 sizes the first.

Practice

Read labs/examples/check_setup.py top to bottom. For each print, say what will appear before running it. Then run it.

What to look for

The point is not the versions. It is that x.shape is a tuple you can index, that x.shape[-1] is the feature dimension by convention, and that you can predict the output of a script you have read. Keep that habit for every script in the course.
