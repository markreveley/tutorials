Module 2 · Arrays and tensors

Reductions, axes, and einsum read aloud

A reduction names the axis it removes. An einsum string names every axis and says which ones disappear. Read both out loud and the shapes take care of themselves.

Reductions remove the axis you name

acts.sum() with no axis reduces everything to a scalar. acts.sum(axis=0) removes axis 0 and keeps the rest; on (batch, seq, d) that sums over prompts and leaves (seq, d). The sentence to say is "sum over the batch axis", and the shape follows: the named axis disappears. axis=-1 names the last axis, axis=(0, 1) names two, and keepdims=True keeps the removed axes as size 1 for broadcasting, as lesson 07 showed.

$ python3 labs/examples/reductions_einsum.py
acts.sum()           -> 276.0 (a scalar: every axis reduced)
acts.sum(axis=0)     -> (3, 4) (batch gone)
acts.mean(axis=1)    -> (2, 4) (seq gone)
acts.max(axis=-1)    -> (2, 3) (d gone)
acts.argmax(axis=-1) -> (2, 3) indices into d
acts.mean(axis=(0, 1)) -> (4,) (one vector per feature)
np.linalg.norm(acts, axis=-1) -> (2, 3)

einsum 'sd,d->s'  : (5,) == x @ d: True
einsum 'sd,td->st': (5, 7) == x @ y.T: True
einsum 'bhqd,bhkd->bhqk': (2, 12, 5, 5) (batch, heads, query pos, key pos)
einsum 'ii->i' diagonal: [5. 5. 5.]
einsum 'ij->ji' transpose: (3, 2)
einsum 'bsd->bd' sums over seq: (2, 4) == acts.sum(axis=1): True
batched matmul 'bsd,de->bse': (2, 5, 3072)

argmax is a reduction that returns indices rather than values, with the same shape rule: logits.argmax(axis=-1) on (batch, seq, vocab) is (batch, seq), the predicted token id at every position. np.linalg.norm(acts, axis=-1) removes d and leaves one length per position, which is exactly the "norm of the residual stream across layers" line you will see in lesson 12.

einsum: name the axes, drop the ones you sum

An einsum string lists one letter per axis of each operand, separated by commas, then -> and the letters of the output. Whenever a label is repeated across operands it is summed over; a label that appears once is kept; in explicit mode the output labels control exactly which axes survive and in what order [NumPy: einsum]. That is the whole notation. The practice is reading it aloud.

StringRead aloudShapesSame as
sd,d->sfor each position s, sum over d of x[s,d]·v[d](5,768),(768,)→(5,)x @ v
sd,td->stfor each s and t, sum over d(5,768),(7,768)→(5,7)x @ y.T
bhqd,bhkd->bhqkper batch and head, every query against every key, sum over d(2,12,5,64)²→(2,12,5,5)q @ k.transpose(-1,-2)
bsd->bdsum over positions(2,3,4)→(2,4)acts.sum(axis=1)
bsd,de->bseapply a (768→3072) weight to every token(2,5,768),(768,3072)→(2,5,3072)acts @ W
ii->ithe diagonal(3,3)→(3,)np.diag

The attention line is the one to memorise. Queries and keys share the batch and head axes, which are kept; they share d, which is summed; the query and key position axes get different letters because they must both survive, and the output order bhqk says "for each query, a row over keys". The causal_attention_pattern stub is this string followed by a scale, a mask, and a softmax over the last axis.

Why reach for einsum instead of @

Matrix multiply works on the last two axes and broadcasts the rest, which is fine until you need to contract a middle axis or keep an axis that @ would merge. einsum makes the contraction explicit and self-documenting: six months later, bhqd,bhkd->bhqk still says what it does, while q @ k.transpose(-1, -2) requires you to recall which axes transpose swapped. Torch has torch.einsum with the same strings, and the einops library extends the idea to reshapes; TransformerLens code uses both heavily, so reading them is a prerequisite for reading the toolkit.

Two reading rules for other people's strings. A letter repeated inside one operand, ii, takes the diagonal. Implicit mode, a string without ->, orders the output alphabetically, which is why np.einsum('ji', a) is a transpose; prefer explicit mode in anything you write.

Finish the shape lab

pairwise_dot is the second row of the table. causal_attention_pattern is the third row, then divide by sqrt(d_head), set every entry with key position after query position to minus infinity, subtract the row maximum with keepdims, exponentiate, and divide by the row sum. The tests check that rows sum to one, that the upper triangle is exactly zero, that the scale is sqrt(64), and that scores of 1e4 do not overflow to NaN, which is what the row-maximum subtraction is for.

In eval and interpretability work

Projecting a (batch, seq, 768) cache onto a (768,) direction is bsd,d->bs. Comparing every token's activation with every other's is sd,td->st. An interpretability result is usually one of these two contractions followed by a claim, and the string is the clearest statement of what was computed.

Pitfall

Summing over an axis you meant to keep because two operands used the same letter by accident. bsd,bsd->b sums over positions and features; bsd,bsd->bs keeps positions. Both run. Read the output letters before you trust the number.

Check your understanding

Read np.einsum("bsd,bd->bs", acts, v) aloud, give its shape for acts (2, 5, 768) and v (2, 768), and say what it computes.

Reveal the reasoning

For each batch item b and position s, the sum over d of acts[b,s,d]·v[b,d]: the dot product of every position with that prompt's own direction vector. Shape (2, 5). Note the difference from bsd,d->bs, which would use one direction for both prompts.
