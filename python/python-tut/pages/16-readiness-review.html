Module 4 · Readiness

Readiness review: cache the residual stream and prove it

Load GPT-2 small, cache residual-stream activations for a set of prompts with hooks, assert every shape, save them with a manifest, and have every lab green. Then grade yourself with the rubric.

The brief

Write one script, labs/cache_run.py, that you would be willing to hand to the interpretability course as the producer of its activations. It must, in order: load GPT-2 small once in eval mode; take a list of at least four prompts of different lengths; batch them with padding and an attention mask; capture the residual stream after every block with forward hooks, using your cache_residual_stream; call assert_cache_shapes on every batch; stack the batches into one (13, n_prompts, seq, 768) float32 tensor or thirteen (n_prompts, seq, 768) tensors; write them with safetensors; and write a manifest from your build_manifest that also records the attention mask, the layer convention, that no BOS token was prepended, and the library versions. Finally, reload the file, run check_manifest, and print the problems list, which must be empty.

Then run every test in the repository that this course owns, and the eval-pipeline tests at the root. All green is the entry condition for the next course.

$ python3 -m unittest discover -s labs -p 'test_*.py' 2>&1 | tail -1
FAILED (errors=95)
$ cd ../.. && python3 -m unittest discover -s dag-tests -p 'test_python_evals.py' 2>&1 | tail -1
FAILED (errors=65)

The two lines above are the state of the shipped stubs, recorded by the verifier: red. Your numbers replace them.

Write the prediction before the run

The roadmap's rigor rule applies to this script too. Before running it, write down: the shape of each saved tensor, the number of tensors, the file size to within ten percent, and which positions of which prompts are padding. Then run and compare. A mismatch in the file size is usually a dtype or an uncached-layer mistake; a mismatch in padding is a mask you did not record. The point of predicting is that the script cannot then surprise you with a plausible wrong artifact.

Reconcile with one other toolkit

Pick either TransformerLens or nnsight and show, for one prompt and one block, that its activation equals yours. For nnsight, equality should be exact. For TransformerLens, state whether you compared raw weights or compatibility mode, and if the latter, centre over d_model before comparing and say so. Write the maximum absolute difference and your tolerance into a short note beside the artifact. This is the step that catches an off-by-one layer or a BOS token, and it is the step people skip.

What this unlocks

Linear Algebra for Interpretability starts from exactly the artifact this review produces: a matrix of residual-stream activations to project, centre, and decompose. Transformer Anatomy rebuilds the forward pass whose outputs you cached and checks it against them. The evals course and statistics course supply the other half of the job: what to measure and how to say what the measurement supports. When a claim in the interpretability course fails on held-out activations, the tools to find out why are the ones on this page.

In eval and interpretability work

The script you just wrote is a data pipeline with a spec, a test, and a manifest. Every eval harness and every interpretability experiment you will run is that pipeline with a different model and a different claim at the end.

Pitfall

Declaring readiness because the tests are green while the script that produced the artifact lives in a notebook with hooks registered at the top level. Green tests on functions plus an unreproducible producer is not ready. Put the producer in a file, run it from a clean interpreter, and keep its output.

Check your understanding

Your script works for four short prompts. A colleague runs it on 200 prompts of up to 800 tokens and it is killed for memory. Which three changes, from this course, do you make first?

Reveal the reasoning

Cache only the blocks the consumer needs rather than all thirteen; write each batch to disk as it completes rather than stacking everything in memory; and confirm no_grad wraps the forward pass so no graph is retained. Then size the batch from the arithmetic in lesson 15: 800 tokens by 768 by 4 bytes is 2.5 MB per layer per prompt. float16 is a fourth option only if the downstream tolerance allows it.

Practice

Write labs/cache_run.py as specified, run it from a fresh interpreter, and keep its output next to the artifact. Then rerun with the prompts in a different order and diff the two manifests.

$ python3 -m unittest discover -s labs -p 'test_*.py' 2>&1 | tail -1
FAILED (errors=95)
What to look for

The manifests differ only in prompt order and the per-tensor checksums that depend on it; shapes, dtypes, versions and convention agree. If anything else differs, something in the script depends on state it should not. Reordering is the cheapest reproducibility test there is, and it is the one a reviewer will try.
