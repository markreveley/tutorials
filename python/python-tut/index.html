Python for Model Internals

Enough Python, NumPy and PyTorch to load a model, read its activations by shape, and test what you built.

The readiness target

Load GPT-2 small, cache its residual stream for a set of prompts with forward hooks, assert every shape, save the activations with a manifest, and have the eval-pipeline labs green.

Start with what this course makes you able to do →

What you will be able to do

  • Read and write everyday Python without translating from Elixir or Rust in your head: names, mutation, dicts, exceptions, generators, dataclasses.
  • Write the test first, then the function, with unittest, and keep the eval-pipeline labs green.
  • Predict the shape of an array expression before running it, including broadcasting, reductions and einsum.
  • Use torch tensors with the right dtype and device, know when you hold a view, and keep autograd out of your inference code.
  • Read a model as a module tree, run GPT-2 small, and get logits, next-token predictions and hidden states.
  • Capture activations with forward hooks, with TransformerLens 4, and with nnsight, and know which numbers differ and why.
  • Save activations and a manifest that another person can check.

How to work through it

This course assumes you can read and write code in some language and have never had to be fluent in Python. Syntax takes weeks; comfort with tensors and shapes takes months, so shapes are the spine of the course: every lesson from 06 on asks you to predict a shape before it shows one. Each lesson has a concrete implication for eval or interpretability work, a worked mechanism, a pitfall, a judgment question with a revealable explanation, and practice with an answer.

Every command shown was executed, and the output printed next to it is the real output from that run, kept in the verification transcript with the package versions that produced it. Nothing was typed in by hand.

Practice locally

Open this file directly in a browser. Reading needs no server or packages. For the terminal work, follow lesson 01 to create a virtualenv with a CPU-only torch, then run from this course directory:

$ python3 labs/examples/check_setup.py
python 3.13.16
numpy 2.5.4
torch 2.14.1+cpu | cuda available: False
transformers 5.20.2
a batch of 2 prompts, 5 tokens each, 768 numbers per token: (2, 5, 768)
x.shape[0] is the batch: 2 | x.shape[-1] is d_model: 768
$ python3 -m unittest discover -s labs -p 'test_environment.py' -v
(no output)

The labs are stubs with tests: shapes.py, hooks.py, manifest.py, and the eval pipeline whose spec is ASSESSMENTS.md. Their tests are red until you implement them. The shape reference and the command reference are there for when you forget.

Part of the path from evals to interpretability

This is the first barrier on the roadmap. It is followed by Linear Algebra for Interpretability, Transformer Anatomy and Interpretability Methods and Rigor. The rigor that lessons here gesture at is taught in Statistics for Evals, and what an eval is for in Understanding LLM Evals. All five share this offline wiki format.

Sources and scope

General explanations are original. Where a lesson quotes specific library behaviour, the annotated bibliography records which official page was checked and for what. The code is deliberately small enough to inspect; it teaches habits, not a library.
