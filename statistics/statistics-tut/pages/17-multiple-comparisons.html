Module 5 · Make defensible decisions

Many metrics, many chances to fool yourself

Account for the comparisons you tried, including the ones you chose not to report.

One dashboard can contain many experiments

Suppose every null hypothesis is true and you perform twenty independent tests, each rejecting at a 5% rate. The probability of no false rejection is 0.95 multiplied by itself twenty times. The probability of at least one is its complement:

P(at least one false rejection) = 1 − 0.95²⁰ ≈ 64.2%

This exact calculation assumes independence and tests with size exactly 0.05. Actual eval metrics can be correlated and discrete, so do not reuse 64.2% as a universal dashboard fact. The mechanism remains: giving yourself more opportunities to select a surprising result changes the decision procedure.

Count the invisible comparisons

A comparison family can include models, prompts, metrics, slices, thresholds, grader variations, and analyses. Trying twenty prompts on a development set is useful search. Calling the best observed score an unbiased estimate of the selected prompt’s future score ignores the selection process.

Write down what was considered, what was selected, and what data are reserved to confirm the choice. A held-out set stops being independent confirmation when its scores guide the next round of prompt edits. This problem can arise even if you never compute a p-value.

Choose an error goal

Familywise error is the probability of at least one false rejection in a specified family. Bonferroni allocates alpha across m tests: with equal allocation, test each at alpha/m. If each individual p-value is valid, this bounds familywise error without requiring the tests to be independent. It can be conservative. [NIST: Bonferroni]

False discovery rate is a different goal: control the expected fraction of false rejections among the rejected hypotheses. It is useful in some discovery settings, but does not promise that a particular claimed improvement is true. Procedures such as Benjamini–Hochberg have assumptions about the p-values and their dependence; selecting a method requires matching the discovery goal and design. [Multiple testing]

Separate confirmation and exploration

Predeclare a primary comparison and important guardrails. Report exploratory slices as exploratory and follow important findings with targeted data. That does not forbid investigating an unexpected severe failure immediately; an operational response and a confirmatory population claim are different decisions.

A useful result includes the analysis history. “We explored twelve slices and observed this regression; it needs independent confirmation” conveys more than presenting the most dramatic slice as if it were the only question asked.

Adjustment does not fix every flaw. A Bonferroni-corrected p-value from an invalid independence model is still invalid. Nor does correction guarantee that a statistically detectable difference matters operationally. The sampling and measurement checks remain prerequisites.

In eval work

Treat a prompt tournament as development. Freeze the chosen prompt and grader, then compare on independent held-out groups using the declared analysis. Report the development search honestly.

Pitfall

Counting only the tests in the final slide deck. The opportunity to select a result came from the analyses you tried, not just the ones you displayed.

Check your understanding

You try thirty prompts, keep the winner, and report its unadjusted p-value on the same tasks. What is missing?

Reveal the reasoning

The selection among thirty candidates is part of the procedure. Use a confirmatory held-out comparison or a suitable planned multiple-comparison analysis, and report the search. An ordinary single-comparison p-value does not account for choosing the winner.

Practice

Predict the direction of the raw familywise error as the test count grows. Compare it with the Bonferroni simulation.

What to look for

The lab deliberately generates independent uniform null p-values. Raw false-positive families become more common; Bonferroni keeps the familywise frequency around or below 5% in this model. Monte Carlo variation remains.
