Module 5 · Make defensible decisions

End-to-end analysis: from file to claim

Reproduce the running results, audit the assumptions, and write a report without letting the largest number choose the conclusion.

A small, inspectable experiment

Work in the course directory. The supplied JSONL files are original synthetic fixtures, generated by labs/make_data.py. You do not need to regenerate them. The commands below read files, perform local calculations, and print results. They do not contact a model or write over your data.

First analyze the independent-task fixture. It has 200 task pairs with one binary outcome per version. Verify the four-cell table from lesson 08: 120 both pass, 24 A-only, 36 B-only, and twenty neither.

python3 labs/stats_lab.py compare

You should see A = 72%, B = 78%, and B−A = +6 percentage points. With 4,000 resamples and seed seven, the paired percentile interval is about −1.5 to +13.5 points. The discordance test reports approximately 0.155. Reconcile all these outputs with the same observations instead of picking whichever looks most decisive.

Move to related tasks

python3 labs/stats_lab.py compare --data labs/data/clustered_tasks.jsonl --unit task
python3 labs/stats_lab.py compare --data labs/data/clustered_tasks.jsonl --unit cluster

Both commands report +10 points. The independent unit changes from 120 tasks to thirty repositories, widening the interval for this fixture. Explain why 360 attempts per version are not 360 independently sampled repositories. Read the caution text as part of the result, not as decorative terminal output.

The cluster bootstrap models independent draws of repositories and preserves all observed task pairs inside them. It does not claim to capture an arbitrary shared provider outage or a changing grader. Those would require additional design information or an amended analysis.

Find the important regression

python3 labs/stats_lab.py compare --data labs/data/clustered_tasks.jsonl --unit cluster --slice sensitive

The sensitive slice worsens by about 16.67 points. Its interval is based on ten repositories and is exploratory in this walkthrough. That still identifies a concrete behavioral concern to investigate. Statistical caution about population inference is not a reason to ignore observed failures.

Produce a report another person can inspect

Fill in the analysis report template in your own notes. Include the target, observed counts, score policy, method, estimate, interval, limitations, slice findings, and next action. Keep a command transcript with the seed and resample count. The shipped verification transcript records the authoring run for comparison; minor Monte Carlo details can depend on Python version.

For the first fixture, a defensible sentence is: “On 200 synthetic independent paired tasks, B improves observed pass rate by six points; the paired percentile interval spans approximately −1.5 to +13.5 points under task-sampling assumptions, so the size and direction of the population gain remain uncertain.” Do not generalize from synthetic cases to a real agent.

Using your own data later

The CLI accepts the same schema via --data. It rejects duplicate task IDs, missing score arrays, nonbinary outcomes, and unequal A/B attempt counts within a task. Those restrictions keep this teaching example auditable. They do not define every valid eval design.

If your data contain missing outcomes, unequal policies, weights, nested or crossed groups, or nonbinary scores, first define the intended analysis. Do not coerce data until they happen to pass the loader. A production analysis may require a richer validated implementation.

In eval work

A reproducible number is only part of a reproducible claim. Keep the selection process and decision rule with the command that calculates the result.

Pitfall

Tuning the bootstrap seed until an endpoint passes a launch gate. Seeds control simulation reproducibility; selecting them for a favorable result is analysis selection.

Check your understanding

Your reproduction matches the mean but not the interval. What do you compare before declaring either implementation wrong?

Reveal the reasoning

Check the independent unit, task weights, inclusion policy, pairing, interval construction, confidence level, quantile convention, resample count, seed, and data version. Different reasonable procedures can produce different intervals; the intended design determines which comparison is meaningful.

Practice

Change the seed once as a computational sensitivity check. Draft the one-paragraph report, then identify the next data collection that would resolve the most important uncertainty.

python3 labs/stats_lab.py compare --data labs/data/clustered_tasks.jsonl --unit cluster --seed 19
What to look for

A seed change should not alter the observed effect. For this fixture, more independent repositories and targeted investigation of sensitive-task regressions are more informative than simply increasing attempts on the same tasks. Real deployment also requires real, appropriately sampled data.
