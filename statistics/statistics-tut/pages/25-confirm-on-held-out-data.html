Module 6 · Screen many candidates

Confirm a screened finding on held-out data

The best candidate from a screen was chosen because it looked good. Only data it has never touched can say how good it is.

The best of many is not a typical one

Return to the all-null screen from lesson 24: 3,000 candidates, fifty observations each, no real association anywhere. The largest |r| in that run was 0.471. That is not a bug in the simulation. Each candidate’s r is a draw from a null distribution centered at zero; take the maximum of 3,000 draws and you get a value far out in the tail. If you had been handed that candidate alone, with its p-value of 0.00056, it would have looked like a discovery.

The same logic applies when real associations exist. Write any candidate’s observed correlation as truth plus noise. Selecting the maximum prefers candidates whose noise happened to be positive, so the winner’s observed value overstates its truth. This is the winner’s curse, a form of selection bias. The upward bias is largest when candidates are many, samples are small, and true effects are weak, which describes a neuron screen exactly. The p-value from the screening data inherits the same problem: it was computed as if this candidate were the only one tested.

Split before you look

The fix is to keep the data used for choosing separate from the data used for scoring. Divide the observations into a screening half and a held-out half before computing anything. Screen on the first half, pick the winner, then compute its correlation on the second half. The held-out value has no selection in it: the winner was chosen without seeing those observations, so its held-out r is an ordinary estimate with ordinary uncertainty.

The lab’s screen command does this split. In the all-null run, the winner on the screening half had r = −0.630 on twenty-five observations and r = −0.098 on the held-out twenty-five: the entire effect was selection. With thirty planted candidates at effect one, the screening winner showed r = 0.777 and held out at 0.739: a real association survives, a little smaller, as expected. On the course fixture of sixty candidates, the winner unit-003 went from 0.794 on its first twenty observations to 0.650 on its last twenty.

A held-out set stays unbiased only while it stays unused. The moment you look at held-out scores, adjust the candidate, and look again, the held-out set has become screening data. The scikit-learn guide describes the same hazard for model tuning: knowledge of the test set leaks into the choices and the score stops reporting generalization. [Held-out data] When a finding matters, three sets are the clean design: screen, confirm, and a final set touched once. A fresh sample collected after the claim is fixed is better still.

Splitting shares the earlier lessons’ requirement to respect structure. Split by document, repository, or prompt family, not by token or attempt. Tokens from the same document on both sides of the split leak the screening data into the confirmation.

Write the prediction before the look

A confirmation is a prediction test. Before scoring on the held-out data, write down four things: which candidate, which direction and rough size the association should have, which held-out observations will be used, and what score would count as failure. A prediction that cannot fail is not a test. “Unit 003’s activation will correlate positively with the date label on the held-out documents, with Spearman ρ above 0.3; below 0.1 we drop the claim” can be checked by anyone with the file.

This does not forbid exploration. Screens are how candidates are found, and looking at the top activations is how explanations are written. The discipline is to label the exploration as exploration, record how many candidates were tried, and give the claim its own untouched data. Lesson 17 made the same point for prompt tournaments; a neuron screen is a tournament with thousands of entrants.

Controls that would also pass if the claim were empty

A held-out correlation of 0.65 is only impressive relative to what an empty claim would score. Run at least one control that should fail if the claim has content.

ControlWhat it doesWhat it rules out
Random candidateScore several unselected units on the same held-out dataHeld-out data that correlate with everything, for example because the label tracks input length
Shuffled labelsPermute the held-out labels across independent units and rescoreA scoring pipeline that produces high values regardless of alignment; also gives the held-out permutation p-value
Trivial-feature baselinePredict the activation from something simple, such as token frequency, position, or the label aloneA specific explanation that adds nothing beyond a generic feature

The random-candidate control calibrates the scale: if ordinary units score 0.3 on this label, 0.65 is strong; if they score 0.6, the label is nearly uninformative about which unit you picked. The shuffled-labels control is the permutation test of lesson 24 applied on the confirmation side. The trivial baseline asks whether your explanation beats a dumb one. An explanation that scores 0.65 when “fires on long inputs” scores 0.62 has not yet earned its wording.

Scoring an explanation of a neuron

The same machinery scores natural-language explanations of what a unit does. Turn the explanation into a prediction: for each token of a text, how strongly should the unit fire? That predicted column, whether written by hand or produced by a model acting as a simulator, is a candidate label. Its correlation with the real activations is the explanation’s score. The released scoring code from an automated-explanation project computes exactly this: the Pearson correlation between real and predicted activations, pooled across all scored text rather than averaged per sequence. [Explanation scoring code]

Everything in this module applies. The explanation was written from the unit’s top-activating examples, so scoring it on those same examples is scoring on screening data. Score on held-out text. Thousands of explanations, one per unit, form a family. Pearson ignores scale, so a simulator that predicts a tenth of the true activation gets the same r as one that predicts it exactly; pair r with a check on magnitude, such as explained variance, when scale matters. And run the controls: an explanation that scores no better than a shuffled one, or than “fires on any capitalized word,” has not been demonstrated.

The rule this course has used since lesson 01 holds for a claim about a model’s internals: name the quantity, name the data it will be tested on, name the control, then look. Understanding LLM Evals treats the measurement side, including how a grader or a simulator is itself validated on held-out cases. The forthcoming Interpretability Methods and Rigor course applies the prediction test to real units in a small language model.

In eval and interpretability work

Report a screened finding as three numbers: the screening correlation, the held-out correlation, and the control’s held-out correlation. If only the first exists, the finding is a hypothesis. A reviewer should be able to ask “what did a random unit score?” and get an answer from the same table.

Pitfall

Reusing the held-out set. After the third round of “adjust the explanation, rescore on held-out text,” the held-out score is a development score with a misleading name. Count the rounds, and keep a final set that is scored once.

Check your understanding

A screen of 4,000 units finds one with r = 0.52 against a label. On a held-out split it scores 0.49, and ten random units score between −0.08 and 0.11 on the same split. A trivial baseline that predicts activation from token position scores 0.45. What has been shown?

Reveal the reasoning

The association is real and survives selection: 0.49 on held-out data against a random-unit range near zero. But the specific claim about the label is weak, because position alone reaches 0.45. The unit may respond to position, and the label may correlate with position. The next step is to test the label after controlling for position, or on held-out text where the two are decoupled.

Practice

Before running, predict how many of the sixty fixture candidates pass p < 0.05 by chance, then compare the raw, Bonferroni, and Benjamini–Hochberg counts. Treat unit-000 as your random-candidate control for unit-003.

python3 labs/stats_lab.py screen --data labs/data/candidates.jsonl
python3 labs/stats_lab.py correlate --candidate unit-003
python3 labs/stats_lab.py correlate --candidate unit-000
What to look for

Three of sixty are expected by chance; the run shows ten raw passes, four of them unplanted. Benjamini–Hochberg keeps five, all planted; Bonferroni keeps none, because sixty candidates at forty observations leave little room under 0.05/60. The control unit’s correlation and its permutation p-value show what an empty claim scores on the same label; the planted unit’s held-out value is the number to report, not its screening value.
