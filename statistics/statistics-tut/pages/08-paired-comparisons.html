Module 2 · Compare systems

Compare models by keeping the pairs

The uncertainty you need is uncertainty in the change, measured on the tasks the two systems share.

Start with one difference per task

Suppose both versions answer the same task. Let its difference be B’s score minus A’s score. A binary task difference is +1 when only B passes, −1 when only A passes, and 0 when they agree. Average these differences to estimate the average change.

NIST’s paired analysis operates on within-pair differences. In evals, retaining task identity often makes this the natural comparison. [NIST: paired] Pairing does not require identical sampled text or matching random seeds: it requires a meaningful shared task or matched unit. Reset the environment so the first version’s work cannot help the second.

Read the running dataset

Outcome on a taskCountContribution to B−A
Both pass1200
A only passes24−24
B only passes36+36
Neither passes200
Average difference = (36 − 24) / 200 = 0.06

B gains twelve net successful tasks out of 200: six percentage points. That is also 78% minus 72%. The paired table preserves how the versions disagree; two headline rates alone do not.

Consider another table with the same margins: 140 both pass, four A-only passes, sixteen B-only passes, and forty neither. The observed difference is still six points, but it arises from twenty discordant pairs rather than sixty. The variation of the differences is different. Identical marginal scores can therefore support different uncertainty statements.

Why pairing often helps

Var(B − A) = Var(B) + Var(A) − 2 Cov(A, B)

The variation of a difference includes how the two scores move together, measured by covariance. If shared task difficulty makes both versions tend to pass and fail together, covariance is positive and pairing can improve precision. That benefit is not unconditional: negative covariance would increase difference variance. Preserve the actual pairing rather than assuming a particular correlation.

Read an interval for the change

For the running fixture, the lab’s seeded percentile bootstrap gives approximately −1.5 to +13.5 percentage points. The observed result favors B, but the interval spans modest harm and substantial benefit. The exact discordance test gives a two-sided p-value near 0.155 under its null model. The next lesson explains what that means.

You should report the change and interval directly. Overlap between separate model intervals is not a reliable substitute for an interval on the paired difference. It discards the covariance that defines the comparison.

In eval work

Join result files by stable task IDs, verify uniqueness, and audit missing counterparts. Pairing rows by their position after one version has dropped failures can silently compare different tasks.

Pitfall

Dropping every task either version failed to complete can select easier cases and change the target. Decide and document the handling of missing counterparts before running the comparison.

Check your understanding

Both versions scored 75%, but they fail different cases. Has the candidate changed nothing?

Reveal the reasoning

The net observed mean change is zero, but behavior may have changed substantially. Inspect discordant cases and slices. A launch decision can depend on which failures appeared, not only their net count.
