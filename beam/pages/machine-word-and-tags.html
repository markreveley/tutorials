The Machine Word & Tags

Every Erlang/Elixir value the VM handles is, at bottom, a single machine word — and that word is self-describing. It carries, in a few of its own bits, the answer to "what am I?" No side table, no separate descriptor. This page is about how one word pulls that off.

One word

A word is the natural unit the CPU and runtime work in. On a 64-bit machine (anything modern) that's 64 bits / 8 bytes; on a 32-bit machine, 32 bits / 4 bytes. It's the BEAM's fundamental cell: every tuple slot, every list-cell pointer, every immediate value occupies one such word.

Because runtime type checks and term comparison happen constantly, the type has to travel with the value. The BEAM solves this by tagging Ch.4.1: it splits every word into a small tag plus a payload.

Two families: immediate vs boxed

This is the correction to the natural beginner model "lists and tuples only hold pointers." Sometimes a slot holds a pointer (boxed); sometimes it holds the value outright (immediate). A small integer in a tuple isn't pointing anywhere — it's sitting right there in the slot.

What decides it — and why it isn't only size

The single rule underneath the split is: a value is immediate when its entire representation fits in one tagged word. But what makes something "fit" differs by type, so there are really four triggers, not just a size cutoff Ch.4.1:

  • Type — categorically (the main driver). Most types are immediate-or-boxed by their very nature, at any size. Always immediate: atoms, the empty list [], local pids, local ports. Always boxed: floats, tuples, maps, binaries, funs, references — even an empty tuple {} is boxed (it still needs its one header word). Non-empty lists are their own category: a list-tagged pointer (tag 01) to a cons cell on the heap.
  • Size — but only for integers. A small integer stays immediate while it fits the payload: 60-bit signed on 64-bit (±2⁵⁹), 28-bit on 32-bit. Step past that and the same number is re-represented as a boxed bignum. Integers are the one type with a true size cutoff.
  • Interning — why an atom is always immediate. An atom's word doesn't hold its characters; it holds an index into the global atom table. A 40-letter atom is still one immediate word — the name's length is irrelevant, only the index travels. (This is the machinery behind rung 5.)
  • Locality — for pids, ports, references. A local pid or port encodes a table index that fits, so it's immediate. An external pid/port/ref — one naming a process on another node — must also carry node identity, creation, and serial; that doesn't fit, so it's boxed.

The float case is the clearest sign it isn't a "small enough?" question: a full 64-bit IEEE double needs the whole word, leaving no room for even a tag — so every float is boxed, never inline, whatever its value. And the payoff of being immediate is concrete: an immediate compares and copies as a single word, with no dereference, and the garbage collector never has to chase it. The VM makes a value immediate whenever it possibly can.

The tag-bit trick (and why it's free)

Here's the elegant part. Pointers to heap objects are aligned: the allocator only ever places an object at an address that's a multiple of the word size. A multiple of 4 ends in 00 in binary; a multiple of 8 ends in 000. So the lowest bits of any genuine pointer are always zero — they carry no information. The BEAM repurposes them as the primary tag Ch.4.2: 

  00  Header (on heap) / return address (on stack)
  01  List  — a pointer to a cons cell
  10  Boxed — a pointer to any other heap object
  11  Immediate — a self-contained value
A correction worth making A common explanation says "8-byte alignment frees the low 3 bits." True on 64-bit — but ERTS only claims two bits for the primary tag, because the scheme must also work on 32-bit (4-byte) words, where only 2 low bits are guaranteed zero Ch.4.2. "At least two bits."

Poke at a word

Pick a value and watch the same 64-bit word reinterpret itself. The tag bits are on the right (least-significant). For the two pointer types, hit Mask & dereference to clear the tag and recover the real address.

Which way to read the bits The word is written like any binary number — most-significant bit on the left, bit 0 on the right. But the tag is decoded from the right: the primary tag is the lowest two bits, and each sub-tag sits in the next bits up. So an atom's 00 10 11 reads right-to-left as immediate (11) → immediate-2 (10) → atom (00) Ch.4.2. Putting the primary tag at the very bottom is what lets a single AND both strip the tag and restore the aligned address.

Two-stage typing

Notice what the pointer's tag does not tell you: whether the boxed thing is a tuple, a map, or a float. There isn't room. The primary tag only says "boxed — go dereference." The precise type lives in the header word, the first word of the object itself, which encodes the subtype and the arity Ch.4.5. So typing is two-stage: 

slot tag says "boxed"  →  mask off tag  →  follow pointer  →  read header word  →  "tuple, arity 4"

Immediates skip all that: their tag (plus sub-tag) fully describes them, which is exactly why comparing two atoms, or two small integers, is a single-word operation.

The takeaway to carry down A value is a self-identifying word. Immediate = the bits are the value. Boxed = the bits are a tagged address; the real type is in the header at that address. Everything in the next rungs — tuples, lists, sharing, atoms — is built from this one idea.
