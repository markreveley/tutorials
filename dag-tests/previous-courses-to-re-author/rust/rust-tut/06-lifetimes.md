# 06. Lifetimes

## Concept

A reference is a pointer plus a promise: *the thing I point at is still alive.*
A **lifetime** is the compiler's name for the region of the program over which
that promise must hold, and lifetime checking is the proof that it does.

Lifetimes are written with a leading apostrophe and appear as generic
parameters:

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

Read it as: *for every region 'a, given two `&str` valid over 'a, I return a
`&str` valid over 'a.* The caller chooses `'a`; the function must work for
every choice.

Structs that hold references are parameterized the same way:

```rust
struct Window<'a> { data: &'a [i32] }

impl<'a> Window<'a> {
    fn new(data: &'a [i32]) -> Self { Window { data } }
    fn sum(&self) -> i32 { self.data.iter().sum() }
}
```

Two more pieces of syntax:

```rust
fn f<'a, 'b: 'a>(long: &'b str, short: &'a str) -> &'a str { .. }  // 'b outlives 'a
static NAME: &str = "rust";                                        // &'static str
fn greeting() -> &'static str { "hello" }                          // literals are 'static
```

Lifetimes are erased before code generation. They cost nothing at runtime;
a `&'a T` and a `&'b T` are the same machine word. A lifetime is a *proof*,
not a value.

## Why

### A lifetime is a set of program points

Model a lifetime as the set of program points at which the reference may still
be used. Then:

- `'a: 'b` ("'a outlives 'b") means **'a ⊇ 'b**: everywhere 'b is live, 'a is
  live too.
- The outlives relation is reflexive and transitive, so `'a: 'a`, and
  `'a: 'b, 'b: 'c ⇒ 'a: 'c`.
- `'static` is the maximum: 'static ⊇ 'x for every 'x, because 'static is the
  whole program.
- References are **covariant** in their lifetime: `&'long T` is a subtype of
  `&'short T` whenever 'long ⊇ 'short. A longer-lived reference is usable
  wherever a shorter-lived one is wanted. (`&'a mut T` is *invariant* in `T` —
  it must be, or you could launder a short reference into a long slot.)

Every borrow in the program generates constraints of the form 'x ⊇ 'y, plus one
per borrowed local: *the loan's region is contained in the region where the
referent is alive.* Borrow checking is solving that constraint system. If a
solution exists, the program is accepted, and the solution is a proof that
every dereference happens while the referent is live.

### Annotations are universal quantification

`fn longest<'a>(a: &'a str, b: &'a str) -> &'a str` is not a hint. It is a
type:

    longest : ∀'a. (&'a str × &'a str) → &'a str

Two consequences follow mechanically.

**Inside the body**, `'a` is opaque — an arbitrary region. The body must
typecheck for *every* 'a, so it may only return references it was given, or
references derived from them. It cannot manufacture a `&'a str` from anything
local, because it knows nothing about 'a.

**At the call site**, the caller instantiates 'a. Since both arguments must
have lifetime 'a, and references are covariant, the compiler picks the largest
'a contained in both referents' live regions — the intersection. That is why
this works:

```rust
let a = String::from("abcd");
let r;
{
    let b = String::from("xy");
    r = longest(a.as_str(), b.as_str()).to_string();  // 'a = the inner block
}
assert_eq!(r, "abcd");   // r is an owned String; nothing borrowed escapes
```

and why keeping the *reference* instead of the `String` would not:

```rust
let r;
{
    let b = String::from("xy");
    r = longest(a.as_str(), b.as_str());   // 'a must include r's uses...
}                                          // ...but b dies here
println!("{r}");                           // error[E0597]: `b` does not live long enough
```

**Choose your annotations to say what is actually true.** If the output cannot
come from an argument, do not tie them together:

```rust
fn first_above<'a>(xs: &'a [i32], bound: &i32) -> Option<&'a i32> {
    xs.iter().find(|&&x| x > *bound)
}
```

Giving `bound` its own (elided, unnamed) lifetime lets it be a short-lived
temporary while the result keeps borrowing `xs`. Writing `bound: &'a i32`
would compile but would force callers to keep `bound` alive as long as the
result — a needlessly strong precondition.

### Why returning a reference to a local cannot typecheck

```rust
fn broken() -> &String {         // error[E0106]: missing lifetime specifier
    let s = String::from("hi");
    &s
}
```

Suppose we wrote the honest signature, `fn broken<'a>() -> &'a String`. Its
type is ∀'a. () → &'a String: the *caller* picks 'a, including 'static. Inside,
`s` is a local; its live region is a subset of the function body, and the body
ends before control returns. The constraint generated by `&s` is
'a ⊆ region(s) ⊆ body. But 'a is universally quantified and the caller may
instantiate it with any region, including ones extending past the call. No
solution. Rejected. ∎

This is not a heuristic about "returning pointers to the stack" — it falls out
of the quantifier. The fix is to return the owned value (`-> String`), or to
take the storage as an argument so the caller's region is available to name.

Note the direction: a function may return a reference *derived from its
arguments*, because those come with caller-chosen regions already in scope.

### The three elision rules

Most signatures need no annotations because the compiler applies three
mechanical rules to elided lifetimes in `fn` signatures and `impl` headers.
They are rules of *inference*, not of semantics: they only fill in what you
could have written.

1. **Each elided lifetime in an input position gets its own fresh parameter.**
   `fn f(a: &str, b: &str)` becomes `fn f<'a, 'b>(a: &'a str, b: &'b str)`.
2. **If there is exactly one input lifetime parameter, it is assigned to every
   elided output lifetime.**
   `fn first_word(s: &str) -> &str` becomes `fn first_word<'a>(s: &'a str) -> &'a str`.
3. **If there are several input lifetimes but one of them is `&self` or
   `&mut self`, the lifetime of `self` is assigned to every elided output
   lifetime.**
   `fn get(&self, k: &str) -> &Value` returns a reference borrowed from `self`.

If an output lifetime is still elided after all three, it is an error — the
compiler will not guess. That is exactly what `fn broken() -> &String` hits:
no inputs, so rules 2 and 3 do not apply.

Rule 3 is the one that bites. In `Window`, `narrow` must *override* it:

```rust
impl<'a> Window<'a> {
    pub fn narrow(&self, lo: usize, hi: usize) -> Window<'a> {   // 'a, not elided
        Window { data: &self.data[lo..hi] }
    }
}
```

Elision would have given `Window<'_>` tied to `&self`, so the result would die
with the receiver. But the data is not owned by `self` — `self` only borrows
it — so the result can outlive `self`, and saying `'a` explicitly is what makes
this compile:

```rust
let data = vec![1, 2, 3, 4];
let narrow = {
    let w = Window::new(&data);
    w.narrow(1, 3)          // w dies here; narrow borrows `data`, not `w`
};
assert_eq!(narrow.sum(), 5);
```

Elision does **not** apply to struct definitions. `struct Window { data: &[i32] }`
is an error; you must name the parameter. The reason is that a struct's
lifetime parameter is part of its public type — callers reason about it — so it
must be written down.

### Structs holding references

`Window<'a>` is not one type; it is a family, one per region. The
well-formedness condition is:

> A value of type `Window<'a>` may only exist at program points contained in 'a.

That is what "cannot outlive the data it views" means formally, and it is why a
struct with a reference field can never be stored somewhere longer-lived than
its referent. In practice: use borrowed fields for short-lived views (parsers,
iterators, windows) and owned fields (`String`, `Vec<T>`) for anything you
intend to store, return, or hand to another thread.

### `'static`, and the two things it means

As a *reference* lifetime, `&'static T` means the referent lives for the entire
program. String literals are baked into the binary, so every literal is
`&'static str`. `Box::leak` produces one deliberately.

As a *bound on a type*, `T: 'static` means something weaker than it looks: "T
contains no references with a lifetime shorter than the program." Every owned
type satisfies it — `String: 'static`, `Vec<i32>: 'static` — because they hold
no borrows at all. `&'a str` does not, for 'a ≠ 'static. So `T: 'static` reads
as *"T is not borrowing anything transient"*, not *"T lives forever"*. That is
the bound `std::thread::spawn` and most trait objects require, and this is the
distinction that makes the requirement reasonable.

Reaching for `'static` to silence a lifetime error is almost always wrong; it
strengthens a precondition instead of fixing the proof.

## Worked examples

```rust
// Elision rule 2 in action — these are the same signature.
fn first_word(s: &str) -> &str {
    match s.find(' ') { Some(i) => &s[..i], None => s }
}
fn first_word_explicit<'a>(s: &'a str) -> &'a str { first_word(s) }

// Two outputs, one input region: slices of the same string.
fn split_once_at<'a>(s: &'a str, sep: char) -> (&'a str, &'a str) {
    match s.find(sep) {
        Some(i) => (&s[..i], &s[i + sep.len_utf8()..]),
        None => (s, ""),
    }
}
assert_eq!(split_once_at("a=b=c", '='), ("a", "b=c"));

// NLL again: the loan ends at its last use, so this is fine.
let mut v = vec![1, 2, 3];
let m = v.iter().max().copied();     // loan dies at the end of this line
v.push(4);
assert_eq!(m, Some(3));

// Outlives bound: 'b at least as long as 'a.
fn pick<'a, 'b: 'a>(primary: &'a str, fallback: &'b str) -> &'a str {
    if primary.is_empty() { fallback } else { primary }   // &'b str coerces to &'a str
}

// 'static is a subtype of every lifetime.
fn takes_short<'a>(_: &'a str) {}
takes_short("literal");              // &'static str used where &'a str is wanted
```

## Exercises

Open `exercises/src/l06_lifetimes.rs`; run:

    cargo test -p exercises l06

- `longest(a, b)` — one region shared by both inputs and the output.
- `first_word(s)` — elision rule 2; no annotations needed.
- `first_above(xs, bound)` — output borrows `xs` only; `bound` must be free to die.
- `Window<'a>` with `new` / `sum` / `narrow` — `narrow` must return `Window<'a>`,
  overriding elision rule 3.
- `split_once_at(s, sep)` — two outputs from one input region; mind `len_utf8`.
- `longest_key(map)` — a reference into a borrowed collection.
- `greeting()` — `&'static str`.
