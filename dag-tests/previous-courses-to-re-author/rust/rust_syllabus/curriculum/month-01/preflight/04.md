# M1-04 preflight

Create the Ubuntu VM on your Mac and inspect its process information as the ordinary ubuntu user. This page contains only M1-04 setup. The guiding agent may help with setup; that help is separate from the independent check.

## Create or open the Ubuntu VM

A virtual machine (VM) runs Linux in software on your Mac; you do not need another physical computer. This exercise needs Linux's /proc process information. Use Multipass with Ubuntu 24.04, locally, without a cloud account.

Check Apple menu → About This Mac: [Multipass supports macOS 14 or later on Intel and Apple Silicon](https://canonical.com/multipass/docs/latest/how-to-guides/install-multipass/). Allow 2 CPUs, 4 GB RAM while running, and space for a 20 GB virtual disk plus downloads. If unavailable, record the constraint with the agent before changing platforms.

If Multipass is missing, download the stable macOS .pkg from [Canonical](https://canonical.com/multipass/install), open it and complete installation. Use Mac administrator credentials only in the system installer. Open a new Mac terminal:

```sh
multipass version
multipass list
```

If syllabus-m1 is absent, create it:

```sh
multipass launch 24.04 --name syllabus-m1 --cpus 2 --memory 4G --disk 20G
```

If it exists, use `multipass start syllabus-m1` instead; never recreate or delete an existing lab to clear a setup error. Enter it:

```sh
multipass shell syllabus-m1
uname -s
whoami
```

Expect Linux and ubuntu. This terminal is now inside Ubuntu. `exit` returns to the Mac. If startup fails, retain the error and `multipass version` for the agent; do not change global networking or disable a firewall.

## Install this lesson's Linux tools

Inside Ubuntu:

```sh
sudo apt update
sudo apt install python3 git procps coreutils man-db nano
```

sudo gives these installation commands administrator authority in the VM. apt refreshes the package list, then proposes packages for confirmation. Python runs the fixture, Git saves work, procps provides ps, coreutils supplies basic file commands, man-db supplies manuals, and nano is the editor. The exercise itself runs as ubuntu, without sudo. Retain any installation error before continuing; do not treat a partial install as success.

## Copy the repository into Ubuntu

A Git bundle transfers committed history locally without credentials or publication. It omits unsaved/uncommitted work and ignored scratch files. Have the agent review and commit current Mac work, including an incomplete attempt, before transferring. Use one checkout at a time.

Return to the Mac with `exit`, then run:

```sh
cd /Users/mark/dev/repos/repos_private/syllabus
mkdir -p scratch/lab-transfer
git bundle create scratch/lab-transfer/to-linux.bundle HEAD
multipass transfer scratch/lab-transfer/to-linux.bundle syllabus-m1:/home/ubuntu/to-linux.bundle
multipass shell syllabus-m1
```

Inside Ubuntu, first run `ls /home/ubuntu`. If syllabus is absent:

```sh
cd /home/ubuntu
git init syllabus
cd /home/ubuntu/syllabus
git fetch /home/ubuntu/to-linux.bundle HEAD
git switch -c lab-work FETCH_HEAD
```

If syllabus already exists, do not initialize it again. Enter /home/ubuntu/syllabus, inspect `git status --short`, and fetch with `git fetch /home/ubuntu/to-linux.bundle HEAD`. Review `git log --oneline HEAD..FETCH_HEAD` and `git diff --stat HEAD FETCH_HEAD`; with a clean checkout run `git merge --ff-only FETCH_HEAD`. On refusal, preserve both histories and ask the agent to reconcile them without resets.

Set repository-local identity once, replacing the sample values with your chosen commit name and email:

```sh
git config user.name "Your Name"
git config user.email "your-chosen-email"
```

These values appear in commits; a private/no-reply email is fine. No password, account login, or global Git configuration is needed. Expect `git status --short` to be empty after initial transfer.

## Save work and return to your Mac

Use this section at session end, not before the exercise. Finish the lesson's exact-resource cleanup first. Review and commit the files listed in the lesson, including the attempt and agent-maintained progress; an incomplete commit is valid. In Ubuntu, from /home/ubuntu/syllabus:

```sh
git status --short
git bundle create /home/ubuntu/from-linux.bundle lab-work
exit
```

The bundle saves committed work on the lab-work branch, not uncommitted changes. Back on your Mac:

```sh
cd /Users/mark/dev/repos/repos_private/syllabus
multipass transfer syllabus-m1:/home/ubuntu/from-linux.bundle scratch/lab-transfer/from-linux.bundle
git status --short
git fetch scratch/lab-transfer/from-linux.bundle lab-work
git log --oneline HEAD..FETCH_HEAD
git diff --stat HEAD FETCH_HEAD
```

After reviewing incoming changes, and only with a clean Mac checkout, run `git merge --ff-only FETCH_HEAD`. If either checkout has edits or the histories diverged, stop and ask the agent to preserve and reconcile both. Do not force an overwrite. Confirm `git log -1 --oneline` and inspect the transferred files before `multipass stop syllabus-m1` on your Mac. Stopping preserves the VM disk; do not delete the VM. Shutdown is housekeeping, not proof the exercise's cleanup worked.
