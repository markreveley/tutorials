## Exercise

1. Add a fixed Environment fixture mapping in the runner tests; it reports only `SYLLABUS_ALLOWED`, `SYLLABUS_SECRET`, and its working directory. Build a test-only parent process that launches the fixture, and use `Command::env` on that parent to give it synthetic values `allowed-example` and `secret-example`. First leave child construction unchanged and observe inheritance. Do not modify the test process's global environment or dump your real variables.

2. Change child construction to clear inherited variables and pass only `SYLLABUS_ALLOWED`. Run the focused tests and record the three returned fields in `labs/m1-13/context-boundary.md`. Use the absolute Python path from preflight; clearing the environment must not silently rely on PATH lookup.

3. Create `scratch/m1-13/work` with `mkdir -p scratch/m1-13/work`. Set the request working directory to its absolute path, `/home/ubuntu/syllabus/scratch/m1-13/work`. For a second case, confirm `scratch/m1-13/missing` is absent using `test ! -e scratch/m1-13/missing && echo 'missing directory ready'`, then use that absolute path. If it exists, preserve it and choose another absent lesson-local name. Record where each failure occurs. For a distinct read-permission case, first preserve any prior scratch copy, then prepare:

```sh
cp labs/fixtures/workload.py scratch/m1-13/unreadable.py
chmod 000 scratch/m1-13/unreadable.py
```

Invoke that fixed copy through the absolute Python executable as your ordinary user. Record whether Python started and what status/message it returned. Restore the copy with `chmod 600 scratch/m1-13/unreadable.py` immediately afterward, including after a failed experiment. Never change permissions on the supplied original.

4. Explain the difference between a child receiving fewer environment values and losing permission to read files. Add the observed limitation to context-boundary.md, citing this experiment. Keep all markers synthetic; do not dump your real environment.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
