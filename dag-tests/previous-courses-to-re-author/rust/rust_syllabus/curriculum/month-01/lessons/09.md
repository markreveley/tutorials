## Exercise

1. Create three text files in `labs/m1-09/inputs/`: `valid.txt` containing `8`, `nonnumeric.txt` containing `many`, and `out-of-range.txt` containing `101`. Leave `missing.txt` absent. The accepted range for this exercise is 1 through 100 inclusive; ignore surrounding whitespace.

2. In `labs/m1-09/src/main.rs`, implement one function parsing text into a limit and another reading a file then calling the parser. Represent read errors and invalid values as distinct error variants. Start with explicit `match`; discuss error propagation before changing it to `?`. The helper functions return errors; runtime input does not justify `unwrap` or `expect`.

3. Have `main` call the file-reading function for the four fixed paths above and print the returned outcome. Run `cargo run --manifest-path labs/m1-09/Cargo.toml` from the repository root. Expect one valid result and three failures, without panics. Preserve the actual variant/message for each in `labs/m1-09/error-table.md`.

4. Trace one failure through both functions to the printed result. Explain which function first knows what went wrong. Add assertions only after you can explain those outcomes; custom Display formatting is optional.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript.
