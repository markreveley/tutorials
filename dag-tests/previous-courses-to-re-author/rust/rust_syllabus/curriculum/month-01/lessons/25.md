## Exercise

1. Copy `labs/m1-24/run-service.sh` to `labs/m1-25/resource-limits.sh` and add only fixed case labels for this experiment. Preserve the ordinary user, Type=exec, fresh unit names, runtime bound, and outside observer. Use a new `syllabus-m1-25-` unit for every case.

2. Run `workload.py cpu --seconds 5` first without CPUQuota and then with `--property=CPUQuota=25%`. Keep all other settings the same. Capture `cpu.stat` repeatedly while the group exists, including usage and throttling fields, along with the configured CPUQuotaPerSecUSec from `systemctl show`. Record loop count and elapsed time as observations, not a calibrated benchmark.

3. Run `workload.py memory --mib 8` with `--property=MemoryMax=128M`, then in a fresh unit run `memory --mib 64` with `--property=MemoryMax=48M`. These sizes include interpreter overhead in the group ceiling. Keep the fixture's maximum 64 MiB allocation and finite runtime; do not increase workload size to force a dramatic failure.

4. Start the outside observer immediately when the service launches. Save available `memory.max`, `memory.current`, and `memory.events` while they exist, then Result, ExecMainCode, ExecMainStatus and the unit journal before releasing it. A cgroup can vanish even with a retained unit. Classify the cause only from captured evidence; a nonzero exit alone is not proof of an out-of-memory kill. If the observer misses the relevant event, keep the result inconclusive and repeat a bounded case.

5. Write configuration/result pairs and their interpretation in `labs/m1-25/results.md`. Explain what the ceiling covers and how CPU quota differs from a deadline. Stop only each recorded unit, reset failed state only after capturing it, and confirm its members are gone. Finish when both mechanisms have observed, justified evidence; an inconclusive required case remains unfinished.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
