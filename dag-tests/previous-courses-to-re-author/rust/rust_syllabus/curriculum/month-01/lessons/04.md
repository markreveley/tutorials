## Exercise

### 1. Observe a process tree

Use two Ubuntu terminals: open each from a Mac terminal with `multipass shell syllabus-m1`, then `cd /home/ubuntu/syllabus`. Terminal A starts the fixture; terminal B observes it.

In terminal A:

```sh
python3 labs/fixtures/workload.py tree --seconds 15
```

The printed JSON gives `parent_pid` and `child_pid`. While they are alive, use terminal B:

```sh
read -r -p 'Parent PID from this run: ' parent_pid
read -r -p 'Child PID from this run: ' child_pid
ps -o pid,ppid,stat,comm -p "$parent_pid,$child_pid"
cat "/proc/$parent_pid/status"
cat "/proc/$child_pid/status"
```

Enter only the positive numeric PIDs printed by this run. `ps` shows process/parent IDs and state; `/proc/PID/status` is Linux's current process information. Record Name, State, Pid, PPid, and Uid in `labs/m1-04/process-tree.md`. If a process ends first, repeat the finite run; never reuse an old PID as a signal target.

### 2. Request termination of the parent

Start a fresh tree in A and capture its new PIDs in B. Confirm both using `ps` before `kill -TERM "$parent_pid"` in B. Repeat the `ps` observations immediately and after the child's finite duration expires. Record the signal request separately from observed process disappearance. A missing `/proc` entry means that observation is too late; it is not a failed fixture launch.

### 3. Compare normal exit and signals

In A run `python3 labs/fixtures/workload.py sleep --seconds 15 &`, then `sleep_pid=$!`. `$!` is the newly launched background job's PID. For the first run, `wait "$sleep_pid"` and immediately `echo $?`. For fresh second and third runs, inspect the new PID with `ps` before using `kill -TERM "$sleep_pid"` or `kill -KILL "$sleep_pid"`, then wait and capture the status. Do not signal a process that has already finished. Record all three outcomes; distinguish the shell's numeric representation from the signal name.

Write `labs/m1-04/reproduce.sh` from your working commands, with fresh PID capture on every run. Record launch → signal request → observed exit as a timeline. Confirm every recorded fixture has finished before leaving; finite runs need no broad cleanup command.
