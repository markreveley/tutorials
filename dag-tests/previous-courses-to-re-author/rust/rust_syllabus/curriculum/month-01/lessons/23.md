## Exercise

### 1. Create the namespace

In the Ubuntu terminal, choose a name and confirm it is absent from `sudo ip netns list` before creating it:

```sh
netns="syllabus-m1-23-$$"
sudo ip netns list
sudo ip netns add "$netns"
sudo ip -n "$netns" link show
sudo ip -n "$netns" route show
sudo ip -n "$netns" link set lo up
```

`$$` adds this shell's PID to the name. `lo` is the namespace's own loopback interface. Record interfaces/routes before and after enabling it; no host route or external connection is added.

### 2. Compare one local endpoint

Create `scratch/m1-23/server` with `mkdir -p scratch/m1-23/server` and inspect it with `ls -A scratch/m1-23/server`; expect no files. Do not serve repository files or private data. Start this empty-directory server in the VM's normal network, with a 20-second outer limit:

```sh
timeout --kill-after=2s 20s python3 -m http.server 8765 --bind 127.0.0.1 --directory scratch/m1-23/server &
server_pid=$!
curl --max-time 2 http://127.0.0.1:8765/
echo $?
sudo ip netns exec "$netns" runuser -u ubuntu -- /usr/bin/curl --max-time 2 http://127.0.0.1:8765/
echo $?
```

If the first curl races server startup, repeat it after the server announces it is listening. If port 8765 is in use, do not kill the unrelated listener: choose 8766 consistently for both clients and server and record that change. The operator enters the namespace, then `runuser` makes the client ordinary `ubuntu`. Record each command's status immediately and actual response/error. A failed host client makes the comparison inconclusive; namespace failure alone proves nothing about this endpoint.

### 3. Connect evidence to the boundary

Compare `ip link show` and `ip route show` outside with the recorded namespace views. Explain the observed reachability in `labs/m1-23/network-boundary.md`. No veth link, bridge, NAT, or global firewall edit belongs in this experiment.

### 4. Clean up and save the reproduction

Let `wait "$server_pid"` reap the finite server wrapper; status 124 means its outer timeout expired. Check `sudo ip netns pids "$netns"` is empty before `sudo ip netns delete "$netns"`, then confirm the name is absent from `sudo ip netns list`. If members remain, inspect their current PIDs and wait for or stop only this lesson's clients before deleting. Save the working sequence in `labs/m1-23/reproduce.sh`, with a trap that records and cleans up this exact namespace on error. Keep the observed result separate from expected behavior.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript.
