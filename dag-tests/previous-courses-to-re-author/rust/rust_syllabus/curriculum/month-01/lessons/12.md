## Exercise

1. Create `capstone/tests/outcomes.rs`. Through the library's public function, test the three cases recorded in M1-11: a successful child, a nonzero child exit, and an executable that cannot start. Derive expected variants from the contract and recorded runs; a test that merely avoids panic is insufficient.

2. Run `cargo test --manifest-path capstone/Cargo.toml --test outcomes`. Record the test names and result in `labs/m1-12/test-evidence.md`. If a test cannot find the Python script, build its path from `CARGO_MANIFEST_DIR` and the repository layout rather than your terminal's starting directory.

3. Temporarily change the implementation so a nonzero child exit is misclassified. Record the exact change and failing assertion, then undo only that deliberate change in your editor. Run the tests again. Do not reset the repository or discard unrelated work to restore the behavior.

4. Run `cargo fmt --manifest-path capstone/Cargo.toml -- --check` and `cargo clippy --manifest-path capstone/Cargo.toml --all-targets -- -W clippy::pedantic`. Apply formatting with `cargo fmt --manifest-path capstone/Cargo.toml` if needed. Investigate warnings that affect these tests; explain any allowance. Name at least two runner promises these three tests do not cover, because the evidence note must not overstate coverage.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
