## Exercise

1. In `labs/m1-20/replay.md`, define allowed transitions for proposed→started→finished and proposed→spawn_failed. A reducer reads events and updates a classification; it does not execute the recorded action. Define Complete(outcome), Incomplete, and Invalid, including checks for schema, run ID, and sequence order.

2. Create four files under `labs/m1-20/histories/` using the M1-19 schema: `complete.jsonl`, `spawn-failed.jsonl`, `truncated.jsonl`, and `contradictory.jsonl`. These are intentionally constructed examples, not observed runs. Keep the original M1-19 log unchanged and label the fixtures synthetic.

3. Implement the reducer as `capstone/src/history.rs`, expose it from the library, and test it in `capstone/tests/history.rs`. Run `cargo test --manifest-path capstone/Cargo.toml --test history`. Test only stored data; no retry or process-spawn function belongs on this path.

4. Record each history's classification and reasoning. Explain two gaps: a child could start before started was recorded, or finish before finished was recorded. These examples explain why a missing terminal event cannot justify automatically rerunning an action; implementing durable execution or retry is not today's task.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
