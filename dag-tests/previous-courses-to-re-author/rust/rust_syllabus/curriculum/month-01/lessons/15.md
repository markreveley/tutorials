## Exercise

1. In `labs/m1-15/src/main.rs`, spawn one worker owning `String::from("worker-a")` and returning its length. Retain the join handle and obtain the result in the caller. Predict before `cargo run --manifest-path labs/m1-15/Cargo.toml`, then explain the ownership transfer and what join waits for.

2. Replace the return path with a channel carrying two messages tagged by worker name. Arrange for the receiving loop to finish once the sender is dropped. A channel is a sender/receiver pair for transferring values; `recv` may wait while senders remain alive. Record the actual messages and shutdown path in `labs/m1-15/concurrency-notes.md`.

3. Add a second worker with its own string and sender. Join both. Before each run, state which ordering follows from program structure and which depends on scheduling. Use a receiver timeout such as `recv_timeout(Duration::from_secs(2))` while debugging so a forgotten sender cannot leave the exercise waiting forever; handle the timeout as a diagnostic, not success.

4. If the compiler rejects data sent to a worker, preserve the diagnostic and discuss which value crosses the thread boundary before repairing it. Do not add shared mutable state just to bypass the error. This lesson's result is the standalone package; no runner change is required.
