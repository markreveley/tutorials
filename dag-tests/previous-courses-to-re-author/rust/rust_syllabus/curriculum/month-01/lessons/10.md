## Exercise

1. Read the capstone README's required end state to understand the library you are starting. Today's deliverable is only its request/outcome types and validation. Define three initial fixture alternatives: Exit(code 0–125), Sleep(seconds 1–30), and Emit(bytes per stream 0–1048576), matching the supplied fixture. Map each to a Python executable, script path, and separate arguments; do not spawn it yet.

2. Define a request with a working directory, a timeout in milliseconds (1–10000 for this lab), and a retained-byte limit per stream (0–65536). In `labs/m1-10/contract.md`, write three valid requests and three invalid requests with the exact rule each invalid request violates. These fields define the interface now; timeout enforcement and output capture are implemented in their own lessons, so validation must not claim they already work.

3. Define distinguishable spawn-error and process-exit outcomes. For a future timeout, leave a design note describing information the caller would need; do not implement timeout behavior. Implement the pure range checks and use `cargo check --manifest-path capstone/Cargo.toml` to verify the types compile.

4. Explain the path from input to validated request. Name one OS condition, such as an executable disappearing after validation, that requires observation when spawning. For argument-passing practice, inspect a `Command` with a synthetic argument containing spaces using `get_args`; constructing it is enough and no arbitrary command needs to run.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
