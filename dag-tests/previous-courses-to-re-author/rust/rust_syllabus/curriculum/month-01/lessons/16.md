# M1-16 — Drain both streams while bounding retained output

**Type:** sequential

**Prerequisites:** [M1-12](12.md) · [M1-15](15.md). Complete the prerequisite evidence and checks first.

## Concept

**Concurrent pipe draining with bounded retention.** Capture stdout and stderr without unlimited retained output or a single-stream pipe deadlock.

## Exercise

1. In the capstone, isolate a helper that accepts byte chunks, keeps at most a configured prefix, counts all bytes received, and marks whether output exceeded the retained limit. Write ordinary tests for zero bytes, exactly the cap, and above the cap. The counts concern bytes, not characters.

2. Integrate two reader threads: each owns one piped child stream. Read chunks and continue draining after the retention limit; wait for the direct child and join both readers. Trace error paths for pipe reads, waiting, and joins. Implementation help is allowed during this learning exercise and must be recorded.

3. Add `capstone/tests/capture.rs` using the fixed Emit request with 262144 bytes per stream and a 4096-byte cap. Run `timeout --kill-after=2s 20s cargo test --manifest-path capstone/Cargo.toml --test capture -- --nocapture`. The external timeout bounds a debugging hang; its termination is a failed/incomplete test, not proof the runner completed.

4. Record observed totals, retained lengths, truncation flags, and completion in `labs/m1-16/capture-results.md`. The fixture emits a finite amount but can still block on a full pipe, which is why the outer timeout exists. Use only direct-child fixtures today. If the timeout fires, inspect the just-created fixture process before cleanup and record which reader remained waiting; do not run a broad kill command.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript.
