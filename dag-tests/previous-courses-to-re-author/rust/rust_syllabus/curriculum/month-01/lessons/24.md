## Exercise

### 1. Start one named service

A transient service is a job created for this run. In the authorized Ubuntu VM, choose a fresh name and confirm it is unused with `systemctl show "$unit" -p LoadState` (expect not-found) before starting:

```sh
unit="syllabus-m1-24-$$.service"
systemctl show "$unit" -p LoadState
sudo systemd-run --unit="$unit" --service-type=exec --remain-after-exit --property=User=ubuntu --property=RuntimeMaxSec=20s --property=TimeoutStopSec=2s --property=KillMode=control-group /usr/bin/python3 /home/ubuntu/syllabus/labs/fixtures/workload.py sleep --seconds 15
```

Type=exec makes executable startup part of the start result. User=ubuntu applies to the workload, while sudo is used by the operator. The time limit bounds the service; RemainAfterExit preserves unit results for review. Do not combine this run with --wait/--pipe/--collect: inspect it asynchronously while it exists.

### 2. Locate membership while running

Immediately read the service identity:

```sh
systemctl show "$unit" -p MainPID -p ControlGroup -p User -p ActiveState
service_pid=$(systemctl show "$unit" -p MainPID --value)
cgroup_path=$(systemctl show "$unit" -p ControlGroup --value)
```

Before the following reads, check MainPID is positive and ControlGroup begins `/system.slice/syllabus-m1-24-`; otherwise stop and inspect the service result.

Then run:

```sh
cat "/proc/$service_pid/cgroup"
cat "/sys/fs/cgroup$cgroup_path/cgroup.procs"
cat "/sys/fs/cgroup$cgroup_path/cpu.stat"
ps -o pid,user,comm -p "$service_pid"
```

Compare the PID/group mapping and user, not just the configuration you asked for. Record actual counters in `labs/m1-24/cgroup-map.md`; membership files may disappear after processes exit.

### 3. Record the outcome, then release the unit

After the fixture ends, use `systemctl show "$unit" -p Result -p ExecMainCode -p ExecMainStatus` and `sudo journalctl -u "$unit" --no-pager`. Record results before `sudo systemctl stop "$unit"`. If it is in failed state, use `sudo systemctl reset-failed "$unit"` only after capturing the failure. Confirm no recorded members remain. Missing counters require a fresh finite run; unit retention does not guarantee a live cgroup.

### 4. Make the procedure repeatable

Save the sequence as `labs/m1-24/run-service.sh`, accepting no arbitrary command. Explain the service manager's authority and the difference between observing a counter and configuring a limit. This script is the starting material for M1-25; do not add resource limits to this lesson's comparison.
