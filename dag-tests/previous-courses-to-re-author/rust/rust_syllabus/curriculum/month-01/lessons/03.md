## Exercise

### 1. Observe a filename with spaces

From the repository root, create `scratch/m1-03/sample text.txt` in your editor containing `sample text`. In Bash, compare:

```sh
cat scratch/m1-03/sample text.txt
cat "scratch/m1-03/sample text.txt"
```

The first command passes two paths; the quoted command passes one. Record actual output/errors in `labs/m1-03/observations.md`. Keep the failing example as evidence rather than changing the filename.

### 2. Observe the two output channels

Run each command in order:

```sh
python3 labs/fixtures/workload.py exit --code 7 > scratch/m1-03/stdout.txt 2> scratch/m1-03/stderr.txt
fixture_status=$?
printf '%s\n' "$fixture_status"
cat scratch/m1-03/stdout.txt
cat scratch/m1-03/stderr.txt
python3 labs/fixtures/workload.py exit --code 7 > scratch/m1-03/combined.txt 2>&1
fixture_status=$?
printf '%s\n' "$fixture_status"
cat scratch/m1-03/combined.txt
```

`>` redirects normal output; `2>` redirects diagnostic output; `2>&1` sends diagnostics to the destination currently used by normal output. Save the status before `cat` replaces `$?`. Expect synthetic stream messages and status 7; record what actually happened. These files are replaced on reruns, so preserve any failed-run evidence first.
