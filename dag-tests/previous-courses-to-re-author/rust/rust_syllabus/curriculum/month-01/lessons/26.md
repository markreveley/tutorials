## Concept

## Exercise

1. Create `labs/m1-26/cleanup.sh` from the reviewed service wrapper. Use only the fixed `tree --seconds 10` fixture in a fresh `syllabus-m1-26-` service, with User=ubuntu, KillMode=control-group, RuntimeMaxSec=3s, and TimeoutStopSec=2s. Keep the observer in your terminal, outside that service.

2. While it runs, record MainPID, ControlGroup, and `cgroup.procs`; inspect each recorded PID's `/proc/PID/cgroup`. After the service limit expires, record Result/ExecMainCode/ExecMainStatus and fresh membership/process observations. An empty group or removed group plus ended recorded processes supports cleanup; a unit name alone does not.

3. Compare with the M1-18 direct-parent run. Record in `labs/m1-26/service-vs-child.md` what the outside observer saw and whether the output reader finished. Preserve a process that remained or an observation that arrived too late as a failed/inconclusive case.

4. Repeat once with the existing runner inside the service and a fixed Tree(10) test request. Add that finite fixture mapping and a fixed demo label if absent; use a runner deadline of 5 seconds so the 3-second service limit acts first. Set `--property=WorkingDirectory=/home/ubuntu/syllabus` on the service, create `labs/m1-26/events/` with mkdir -p, and use an absolute event-file path in that directory. Preserve each actual M1-19-format event prefix there. Explain a missing finished event from its contents; do not manufacture one. Document the request label and event destination in the script/notes.

5. Capture the unit outcome before stopping/resetting only that unit. Confirm recorded descendants are gone. Preserve code changes, outside observations, and the actual event prefix together. This exercise demonstrates process cleanup; it cannot establish whether an external effect occurred before termination.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
