## Exercise

1. In `labs/m1-17/deadline-timeline.md`, define the result when a child finishes normally, the deadline is observed, termination fails, or wait fails. Use `std::time::Instant` for elapsed time: this clock measures intervals rather than calendar timestamps.

2. Implement a deadline loop using `try_wait` with a short bounded polling interval (10 ms is a starting value). On deadline expiration, request direct-child termination and wait to reap it; preserve OS failures. Explain which state owns the child and readers on every return path.

3. Add `capstone/tests/deadline.rs`: compare Exit(0) with Sleep(5) under a 500 ms deadline. Run `timeout --kill-after=2s 15s cargo test --manifest-path capstone/Cargo.toml --test deadline -- --nocapture`. Record start, deadline observation, termination request, wait result, and reader completion when those events are actually observed.

4. Check a tolerant interval rather than exact millisecond equality. A loaded machine can delay scheduling; an outer-timeout failure must stay visible. Explain the race where the child finishes near the deadline. The tree fixture remains outside this exercise because this implementation owns only a direct child; that limitation belongs in the evidence note.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript.
