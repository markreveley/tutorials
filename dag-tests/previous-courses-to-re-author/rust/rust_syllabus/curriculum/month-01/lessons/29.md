## Exercise

1. Review and locally commit the current implementation and documentation with the guiding agent. From `/home/ubuntu/syllabus`, run `git status --short`; the files needed for reproduction must be committed. Create a separate checkout without modifying this one:

```sh
repro_root=$(mktemp -d /home/ubuntu/syllabus-m1-29.XXXXXX)
git clone --no-local /home/ubuntu/syllabus "$repro_root/repo"
```

The source repository remains intact. Record the resulting path and commit. This tests a clean checkout on the same VM, not a second-host installation.

2. In the new checkout, run the capstone README's build/tests and `cargo test --locked --manifest-path capstone/Cargo.toml`. Then reproduce the documented M1-27 success and negative cases with fresh lesson names. The wrapper's absolute repository/binary paths must resolve to this new checkout; if they still point at the original, preserve that as the first reproduction failure.

3. Correct one documented assumption at a time in the original working repository: paths, tool versions, fixed inputs, authority, or retained artifacts. Make a reviewable commit there. From the same terminal that holds repro_root, run `git -C "$repro_root/repo" status --short` and `git -C "$repro_root/repo" fetch origin lab-work`. Review the incoming diff; with a clean clone, run `git -C "$repro_root/repo" merge --ff-only FETCH_HEAD` before rerunning. Preserve any divergent work for the agent to reconcile. Do not copy untracked source files across to hide a missing commit. Keep the failed and corrected invocations in `labs/m1-29/reproduction.md` in the original repository.

4. Build `labs/m1-29/evidence-index.md` linking each claimed guarantee to its relevant result and limitation. Record actual Rust/Python/kernel/systemd versions and the fixed resource bounds. Clean up exact service/namespace resources from each run and record the retained reproduction directory. Keep that directory until its evidence is copied; do not delete it as an automatic cleanup step.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
