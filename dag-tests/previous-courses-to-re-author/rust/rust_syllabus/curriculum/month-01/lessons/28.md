## Exercise

1. Create `capstone/tests/prefix_property.rs`. Use Proptest to generate at most 16 chunks, each at most 128 bytes, and a retained limit from 0 through 256. Use 64 cases initially. A property states what should hold for every generated input; shrinking searches for a smaller failing example.

2. Build an expected result independently by flattening the generated chunks into a vector and taking its first cap bytes. Compare retained bytes, total count, and truncation with the helper's result. Do not call the same helper to compute both actual and expected values.

3. Run `cargo test --manifest-path capstone/Cargo.toml --test prefix_property`. Temporarily introduce one off-by-one or chunk-boundary defect, rerun, and record the failure and minimized input in `labs/m1-28/property-evidence.md`. Restore only your deliberate edit and rerun. Keep any regression seed/file the tool creates, after review, so the failure can be reproduced.

4. Explain why different chunk partitions should preserve the same result and which behavior the property does not exercise (for example scheduling or OS process cleanup). This test uses memory values only. No subprocess or Linux setup is required; the process-level tests from earlier lessons remain separate evidence.

Keep commands and actual results in the named evidence file; use the attempt's **Work and observations** for help received or a pointer to that file, not a duplicate transcript. Under **Learner explanation**, briefly compare your result with your prediction and identify remaining uncertainty. Implementation help during the exercise is allowed and must be recorded.
