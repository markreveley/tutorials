Module 3 · The whole model

The full forward pass from raw weights

The capstone: load Hugging Face's state dict, write the model in plain tensor operations, and match the reference logits. This is the readiness test's first half.

The task

Everything from lessons 02 to 09 is one function. Given token ids and the 148 weight tensors, produce logits that agree with GPT2LMHeadModel. The stub in labs/gpt2_from_scratch.py gives you the loader and asks for six functions: layer_norm, gelu_new, causal_attention, mlp, forward_with_cache, and forward. The reference solution used to produce this course's transcripts is about 90 lines; a readable version of yours should be under 200. The tests compare logits, every residual checkpoint, every attention pattern, and the MLP activations, then repeat the comparison against TransformerLens 4 and nnsight.

The largest logit on the prompt is about 134 and the largest discrepancy is 3.05e-05: agreement to roughly seven significant figures, which is float32 arithmetic done in a different order. The tests allow 1e-3 on logits and residuals, generous enough to admit any correct implementation and tight enough to reject every mistake in the list below.

The skeleton

Here is the structure, written out as the operations rather than as code, with the Hugging Face tensor each step uses. x is the residual stream, shape (batch, seq, 768).

  1. Embed. x = wte.weight[ids] + wpe.weight[0:seq]. Record embed, pos_embed.
  2. For each block i = 0 … 11:
    1. Record resid_pre.i = x.
    2. a = layer_norm(x, ln_1.weight, ln_1.bias); attn_out, pattern = causal_attention(a, block, 12). Record pattern.i, attn_out.i.
    3. x = x + attn_out. Record resid_mid.i.
    4. m = layer_norm(x, ln_2.weight, ln_2.bias); mlp_out, post = mlp(m, block). Record mlp_post.i, mlp_out.i.
    5. x = x + mlp_out. Record resid_post.i.
  3. Finish. ln_final = layer_norm(x, ln_f.weight, ln_f.bias); logits = ln_final @ wte.weight.T.

Inside causal_attention: qkv = a @ c_attn.weight + c_attn.bias, shape (batch, seq, 2304); split the last axis into three 768-blocks; reshape each to (batch, seq, 12, 64) and transpose to (batch, 12, seq, 64); scores = q @ kᵀ / 8; fill the strict upper triangle with −∞; softmax over the last axis; z = pattern @ v; transpose back and reshape to (batch, seq, 768); out = z @ c_proj.weight + c_proj.bias. Inside mlp: post = gelu_new(m @ c_fc.weight + c_fc.bias), out = post @ c_proj.weight + c_proj.bias.

The ways it goes wrong

These are the errors the tolerance is designed to catch, in roughly the order people make them. Each is also a lesson's pitfall.

MistakeSymptomLesson
Transposing Conv1D weights (treating (768, 2304) as nn.Linear)Shape error, or garbage logits if shapes happen to match (c_proj is square)07, 11
Exact GELU instead of the tanh approximationLogits off by ~1e-3 to 1e-2, argmax usually agrees07
Sample variance in layer normSmall uniform drift, grows with depth04
Splitting heads as (batch, seq, 64, 12) instead of (batch, seq, 12, 64)Patterns wrong at block 0; the HF comparison of pattern.0 fails first06
Mask with 0 instead of −∞, or no maskRows do not sum to 1, or upper triangle nonzero; later positions leak into earlier ones05
Forgetting the attention or MLP biasResiduals off from block 0; the stream-identity test still passes because the error is consistent03
Applying ln_f before recording resid_post.11, or using hidden_states[12] as resid_post.11resid_post.11 off by hundreds; everything else fine09, 13
Unembedding with wte instead of wteᵀShape error (768 vs 50257)09

Reading the diff

When the numbers disagree, the cache tells you where. The tests check resid_post.i for every i; the first failing block is where the bug lives, and within it, pattern.i (attention scores), attn_out.i (value/output path), and mlp_post.i (GELU and the up-projection) locate it further. A bug in layer norm shows up at resid_post.0 already; a bug only in ln_f shows up only in the logits. Discrepancies that are small (1e-5) and grow slowly with depth are accumulation-order noise and are not bugs. Discrepancies that are constant across positions are usually a missing bias; discrepancies confined to position 0 usually involve the mask.

In interpretability work

Owning a forward pass you wrote is what lets you trust a hook. When a library reports an activation under some name, you can compute the same quantity yourself and check it to 1e-4, which is exactly what lesson 13 does. Every intervention experiment (ablating a head, patching a residual vector) is a modified forward pass; if you can write the unmodified one, the modified one is a few lines.

Pitfall

Optimising before matching. Fused QKV reshapes, in-place masking, einsum tricks, and half precision all change the accumulation order or the rounding. Write the obvious version, match to 1e-4, keep it as the oracle, and only then make a fast version that you test against it.

Check your understanding

Your logits match Hugging Face to 2e-3 everywhere and the argmax agrees at every position, but the test fails. What is the most likely cause, and why does the test not accept 2e-3?

Reveal the reasoning

Most likely the exact GELU was used instead of gelu_new; a float32 accumulation-order difference is two orders of magnitude smaller than 2e-3, so a 2e-3 discrepancy is a systematic error. The tolerance rejects it because small systematic errors compound: at a different prompt or a longer sequence the argmax can flip, and more importantly any activation you later compare to a library's will carry the error, which makes the naming map in lesson 13 untrustworthy.

Practice

Implement the six functions, then run the tests and the comparison. Keep the output of the first comparison that passes; it is your evidence for the readiness review.

python -m unittest discover -s labs -p 'test_gpt2_from_scratch.py' -v
python labs/anatomy.py compare --tools
What to look for

A passing run shows every max-difference at 1e-4 or below and "argmax next token agrees at every position: True"; the TransformerLens line (no_processing) and the nnsight line agree with your cache to the same order. The tests also check that your cache has 148 parameter tensors, that patterns match attentions to 1e-4, and that the stream equals the sum of its writes.
