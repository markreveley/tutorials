Shapes and parameter counts: deriving 124M from the config

Every tensor in GPT-2 small, its shape, and its size, added up by hand to the exact number the weights contain, with one historical discrepancy explained.

Every tensor

The state dict has 149 entries: two embedding tables, twelve tensors in each of twelve blocks, two for the final layer norm, and the tied output matrix. Listing block 0 is enough, since blocks 1 to 11 have identical shapes:

Every two-dimensional weight is stored as (in, out) because the layers are Conv1D modules, which compute x @ weight + bias [transformers GPT-2 code]. The exception is lm_head.weight, an nn.Linear stored as (out, in) = (50257, 768), which is why the unembedding is wteᵀ in the capstone: it is the same tensor, used transposed.

Two observations fall out. The embedding table is 31% of the model; the attention and MLP matrices of one block are about 7.1M, of which the MLP is two thirds. And biases and layer-norm parameters are a rounding error: about 0.1% of the total.

117M or 124M?

The GPT-2 paper's Table 2 lists the smallest model as 117M parameters with 12 layers and d_model 768 [Radford 2019]. The OpenAI model card for the same release describes the sizes as 124 million, 355 million, 774 million, and 1.5 billion [GPT-2 model card]. The weights in the Hugging Face checkpoint contain 124,439,808 learned scalars, and the derivation above reproduces that number from the config. This course therefore says 124M, and treats the paper's figure as a number whose derivation is not given. The method is the point: when two sources disagree about a model, the weights settle it, and the command that counted them is recorded.

Shapes in flight

Parameters are static; activations depend on the input. For batch b and sequence length s:

ActivationShapeTransformerLens name
token ids(b, s)input
residual stream(b, s, 768)blocks.i.hook_resid_pre / _mid / _post
q, k, v, z per head(b, s, 12, 64)blocks.i.attn.hook_q / _k / _v / _z
attention scores and pattern(b, 12, s, s)blocks.i.attn.hook_attn_scores / hook_pattern
MLP hidden(b, s, 3072)blocks.i.mlp.hook_pre / hook_post
logits(b, s, 50257)return value of run_with_cache

TransformerLens keeps the head axis after the sequence axis for q, k, v, and z, and before it for scores and patterns; Hugging Face's internal attention uses (b, 12, s, 64) throughout. Lesson 13's table records which is which, and the shapes column of the names output is the check.

In interpretability work

Shape assertions are tests. A hook that receives (1, 12, 6, 6) when you expected (1, 6, 12, 64) has told you that you hooked the pattern, not z; an assert tensor.shape == (b, s, 768) at the top of every analysis function costs nothing and catches the silent transposes that produce plausible-looking nonsense. Know the shapes table well enough to write those asserts without looking.

Pitfall

Counting len(state_dict) as the number of parameter tensors, or summing numel() over the state dict. The state dict has 149 entries because the tied lm_head.weight appears under its own name; the model has 148 distinct parameter tensors. Summing over the state dict double-counts 38.6M.

Check your understanding

GPT-2 medium has 24 layers and d_model 1024, with the same vocabulary, context length, and 4× MLP ratio. Derive its parameter count to the nearest thousand without running anything, then say which single line of the derivation you would check against the weights first.

Reveal the reasoning

wte 50,257 × 1,024 = 51,463,168; wpe 1,048,576; per block: ln 4,096 + c_attn 1,024 × 3,072 + 3,072 = 3,148,800 + c_proj 1,048,576 + 1,024 = 1,049,600 + c_fc 1,024 × 4,096 + 4,096 = 4,198,400 + mlp c_proj 4,096 × 1,024 + 1,024 = 4,195,328, total 12,596,224 per block; 24 blocks = 302,309,376; ln_f 2,048; total ≈ 354,823,168, which is the "355M" of the model card. Check the head count first (the derivation does not depend on it, but d_head = 1024/16 = 64 confirms the config), and then c_attn's shape, since a model with separate q, k, v matrices would store three (1024, 1024) tensors instead.

Practice

Add up the five per-block lines by hand and confirm 7,087,872. Then write the GPT-2 medium derivation above into a short Python expression and check it against the model card's 355M.

python labs/anatomy.py shapes
python labs/anatomy.py config
What to look for

3,072 + 1,771,776 + 590,592 + 2,362,368 + 2,360,064 = 7,087,872. The medium derivation gives 354,823,168, which rounds to 355M. If you have the medium checkpoint cached, sum(p.numel() for p in model.parameters()) will confirm it; if not, the derivation is your only evidence and you should say so.
