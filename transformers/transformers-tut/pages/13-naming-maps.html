Module 4 · Tooling and variants

Naming maps: the same activation in Hugging Face, TransformerLens 4, and nnsight

Three libraries, three vocabularies, one set of tensors. The table on this page was produced by running all three on the same ids and printing the differences.

Loading the model three ways

Hugging Face is the ground truth: GPT2LMHeadModel.from_pretrained("gpt2"), with output_hidden_states=True and output_attentions=True on the call. With transformers 5, attentions are returned only when the model is loaded with attn_implementation="eager"; the default fused kernel returns an empty tuple.

TransformerLens 4 removed the HookedTransformer class that older tutorials use. The replacement is a bridge over the Hugging Face model [TransformerLens 4 migration]:

from transformer_lens import TransformerBridge
bridge = TransformerBridge.boot_transformers("gpt2")
bridge.enable_compatibility_mode(no_processing=True)   # raw weights; omit no_processing for HookedTransformer numerics
logits, cache = bridge.run_with_cache(ids)
cache["blocks.5.hook_resid_post"]

Compatibility mode's defaults fold layer norms, centre the writing weights, and centre the unembedding, reproducing what HookedTransformer.from_pretrained used to do; no_processing=True keeps the raw weights so that activations match Hugging Face [TransformerLens compatibility mode]. The call rewrites weights in place and must not be repeated on the same bridge.

nnsight wraps the Hugging Face model and lets you name activations by the module path [nnsight quickstart]:

from nnsight import TransformersModel
model = TransformersModel("gpt2", task="text-generation", device_map="cpu", dispatch=True)
with model.trace(ids):
    mlp5 = model.transformer.h[5].mlp.output.save()    # request modules in the order they run
    h5 = model.transformer.h[5].output.save()
    logits = model.lm_head.output.save()

Three nnsight rules, all verified while writing this page: pass task explicitly when offline; call .save() on anything you want after the block; and request modules in execution order, since asking for h[5].output and then h[5].mlp.output raises OutOfOrderError [nnsight: getting activations]. A trace block must also run from a file or notebook cell; the course's tool is a file for that reason.

Every row agrees to 1e-5 or better. Reading the table:

  • Residual stream. Hugging Face's hidden_states[i] is the stream entering block i, so TransformerLens's blocks.i.hook_resid_pre is hidden_states[i] and hook_resid_post is hidden_states[i+1]. In nnsight, h[i].input and h[i].output.
  • The last hidden state is not resid_post.11. hidden_states[12] is after ln_f; it matches ln_final.hook_out and ln_f.output, and differs from blocks.11.hook_resid_post by hundreds. The stream after block 11 is available from TransformerLens and from nnsight's h[11].output, but not from the Hugging Face tuple.
  • Sub-block writes. Hugging Face exposes attention and MLP outputs only through hooks on the sub-modules; TransformerLens has hook_attn_out and hook_mlp_out; nnsight has h[i].attn.output[0] and h[i].mlp.output. The attention module returns a tuple (output, attention weights or None), hence the [0]; the MLP and the block return a plain tensor in transformers 5.20.2, so h[i].output[0] would index the batch axis and silently drop a dimension.
  • Patterns and neurons. attentions[i], blocks.i.attn.hook_pattern, and a hook on the attention module all give (batch, head, query, key). MLP activations after GELU are blocks.i.mlp.hook_post and h[i].mlp.act.output.
  • Layer-norm hooks are pre-affine. The note line in the output shows that ln_final.hook_normalized times ln_f.weight plus ln_f.bias reproduces hidden_states[12]; hook_normalized itself does not. The same holds for every ln1 and ln2 hook.
  • BOS. bridge.to_tokens(text) prepends <|endoftext|> (50256) by default, so a TransformerLens run on text has one more position than a Hugging Face run on the same text and every position index shifts by one. This page passed ids directly to all three libraries.

note: ln_final.hook_normalized is before the affine step: max |hook_normalized * weight + bias - hidden_states[12]| = 7.2e-05; the same holds for blocks.N.ln1.hook_normalized and ln2.hook_normalized
with default processing: logits differ by a per-position constant (center_unembed): max|diff - row mean| = 5.3e-05; log-softmax max diff = 3.8e-05
resid_post after removing each vector's mean over d_model (center_writing_weights): max diff = 4.9e-04

The last two lines explain the discrepancies. Logits differ by a per-position constant (108.9 at most) because of center_unembed, and the difference vanishes after removing each row's mean; log-softmax agrees to 3.8e-05. Residual vectors differ by their mean over d_model because of center_writing_weights, and agree to 4.9e-04 once both are centred; the next layer norm removes that mean anyway, so the model's function is unchanged. The attention pattern and the MLP activations match in both modes because folding and centering are exact rewrites. The full cache has 493 entries; the block-5 list at the bottom of the output is the catalogue of hook names for one block, produced by the installed package rather than copied from documentation [TransformerLens hooks].

In interpretability work

Record which library, which processing mode, and which tokenization convention produced every number in a write-up. "resid_post at layer 5, position 3" means different vectors under default and no-processing modes (differing by a mean component), and different positions under BOS and no-BOS tokenization. A result that reproduces only under one library's defaults is a result about the defaults until you have shown otherwise.

Pitfall

Reading an older tutorial's HookedTransformer.from_pretrained("gpt2") and trying to install an older TransformerLens into a shared environment to make it work. The bridge API gives the same cache keys; the migration guide maps the old names to the new ones [TransformerLens 4 migration]. If an older tutorial's numbers are from processed weights, use the default compatibility mode and expect raw-weight comparisons to differ as above.

Check your understanding

A colleague reports that "the layer-5 residual stream at the cat token has norm 85" using Hugging Face, and another gets 86 with TransformerLens default mode and "the same prompt." List the questions that must be answered before deciding whether these agree.

Reveal the reasoning

Which stream: hidden_states[5] (entering block 5) or hidden_states[6] (after it)? Did TransformerLens prepend BOS, shifting "the cat token" by one position? Did default processing centre the writing weights, which changes the norm by removing the mean component? Were the same ids used (lesson 01)? Any of these can account for a 1-unit difference; until they are fixed, the two numbers are not measurements of the same quantity.

Practice

Run the table for block 0 and for block 11. At block 11 the Hugging Face column for the residual after the block says it is not exposed; confirm that TransformerLens and nnsight still agree with each other there.

python labs/anatomy.py names --layer 0
python labs/anatomy.py names --layer 11
What to look for

At layer 0 every row matches as at layer 5. At layer 11 the "residual after block" row compares nnsight's h[11].output with TransformerLens's blocks.11.hook_resid_post (the Hugging Face column cannot supply it), and they agree to about 1e-4; hidden_states[12] still matches ln_final.hook_out.
