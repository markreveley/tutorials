Module 4 · Tooling and variants

Architectural variants: GPT-2 versus Llama-style models

RMSNorm, rotary positions, SwiGLU, grouped-query attention, and no biases. Each is a small change to one lesson of this course, verified against the papers and the installed model code.

The family

Most open models you will inspect after GPT-2 share a recipe that the LLaMA paper lays out in three sentences: pre-normalisation with RMSNorm, SwiGLU in place of ReLU, and rotary positional embeddings in place of absolute ones [Touvron 2023]. The Qwen3 technical report describes its dense models with the same components plus grouped-query attention and QK-Norm, and with the QKV bias of Qwen2 removed [Qwen3 report]. The installed Hugging Face code for both model families was read to confirm the exact operations [transformers Llama and Qwen3 code]. Here is the map from this course's lessons to what changes:

RMSNorm

Zhang and Sennrich proposed dropping LayerNorm's re-centering and normalising by the root mean square alone [Zhang & Sennrich 2019]. The installed Llama code computes, in float32, x · rsqrt(mean(x²) + ε), then multiplies by a learned weight; there is no bias and no mean subtraction [transformers Llama and Qwen3 code]. Lesson 04's demo computed it on [1, 3, 5, 7]: rms = √21 = 4.5826 and the output is [0.2182, 0.6547, 1.0911, 1.5275]. Two consequences for analysis: the all-ones direction is no longer deleted by normalisation, so a write along it does reach the next sub-block; and folding works the same way (scale the next matrix's rows by the weight), with no bias to absorb.

Rotary positions

Su et al. encode position by rotating the query and key vectors so that their dot product depends on the relative distance between positions [Su 2021]. In the installed code, rotate_half splits each head's 64 (or head_dim) coordinates into two halves and forms [−x₂, x₁]; then q_embed = q·cos + rotate_half(q)·sin with cos and sin depending on position and on a per-pair frequency; keys get the same treatment, values do not [transformers Llama and Qwen3 code]. The dot product of a rotated query at position i with a rotated key at position j depends on i − j, not on either alone.

For interpretability this changes what the QK circuit is. In GPT-2 the score is xi W_Q W_Kᵀ xjᵀ, one fixed bilinear form. With RoPE a position-dependent rotation sits between W_Q and W_Kᵀ, so the effective QK matrix is different for each relative offset, and a "which directions does this head match?" analysis has to be done per offset or on the unrotated weights with the rotation treated separately. The OV circuit is untouched, and there is no hook_pos_embed; the position information enters inside attention.

Grouped-query attention

Ainslie et al. introduced grouped-query attention: an intermediate number of key/value heads, more than one but fewer than the number of query heads [Ainslie 2023]. Qwen3-0.6B has 16 query heads and 8 key/value heads [Qwen3 report]. In code, repeat_kv expands the key and value tensors from (b, n_kv, s, d_head) to (b, n_q, s, d_head) by repeating each key/value head for the query heads in its group [transformers Llama and Qwen3 code]. The attention pattern tensor still has one row-matrix per query head, shape (b, n_q, s, s); two query heads in the same group have different queries and different patterns but read identical keys and values. The KV cache of lesson 12 shrinks by the ratio n_q/n_kv, which is why the design exists.

For a head claim this means "head 7's value vectors" is shorthand for "key/value head 7 // group_size's value vectors," shared with its siblings; an ablation of one query head's output does not remove the information from its group-mates.

QK-Norm and no biases

Qwen3 applies RMSNorm to each query and key vector over the head dimension before the rotation; the installed code has q_norm and k_norm of size head_dim [transformers Llama and Qwen3 code]. This bounds the attention scores, since normalised vectors have fixed length. It also means the raw W_Q W_Kᵀ product is further from the score the model actually uses: there is a normalisation and a rotation between them. Removing the biases (both families) simplifies one thing: the stream is a sum of pure matrix products, with no constant vectors added per layer.

What changes for the tools

TransformerLens's config carries fields for each of these: normalization_type (LN or RMS), positional_embedding_type (standard or rotary), gated_mlp, n_key_value_heads, and use_qk_norm; for GPT-2 the bridge reports LN, standard, False, None, and False, and the hook names in lesson 13 are the ones to expect for GPT-2. For a Llama-style model the same residual and pattern hooks exist, there is no positional-embedding hook, mlp.hook_post is the gated product, and keys and values carry fewer heads than queries until expanded. In nnsight, module paths follow the Hugging Face class: model.model.layers[i], .self_attn, .mlp, .input_layernorm, rather than transformer.h[i]. Read the printed module tree before writing a path.

In interpretability work

Port a method one lesson at a time. A neuron result moves to Llama with one change (hook the gated product); a QK-circuit result needs rethinking (rotation per offset); a direct-logit-attribution result needs the RMSNorm scale instead of the LayerNorm scale and no bias term. Write the GPT-2 version first, match it to 1e-4 as in lesson 10, then change one component and re-verify against the installed model code rather than against a diagram.

Pitfall

Assuming a model is "Llama-style" from its name. Model families differ in details that break tooling: tied or untied embeddings by size (Qwen3 switches at 8B), the presence of QK-Norm, attention biases (present in Qwen2, removed in Qwen3). The config file and the modeling source in the installed package are the ground truth; the paper is a summary.

Check your understanding

You have a GPT-2 experiment that projects every head's W_V W_O onto the unembedding to find heads that promote a token, and it uses hook_pos_embed as a baseline. Which parts carry over to Qwen3-0.6B unchanged, which need adjustment, and which have no equivalent?

Reveal the reasoning

W_V W_O per query head carries over, with the caveat that W_V belongs to a key/value head shared by two query heads, so the matrix repeats within a group. Projection onto the unembedding carries over; the final normalisation is RMSNorm, so the scale factor changes form. hook_pos_embed has no equivalent: there is no position vector in the stream. Any baseline built from it must be replaced, for example by the embedding alone, and the write-up should say the baseline differs.

Practice

The RMSNorm line of the layer-norm demo is the only variant computation this course can run without a second model cached. Recompute it, then open the installed modeling_llama.py and modeling_qwen3.py and locate the five operations in the table: the norm, rotate_half, repeat_kv, the MLP forward line, and q_norm/k_norm.

python labs/anatomy.py layernorm-demo
What to look for

√((1 + 9 + 25 + 49)/4) = 4.5826 and [1, 3, 5, 7]/4.5826 = [0.2182, 0.6547, 1.0911, 1.5275]. In the installed source, LlamaRMSNorm.forward, rotate_half, apply_rotary_pos_emb, repeat_kv, and LlamaMLP.forward are each a few lines; Qwen3Attention adds q_norm and k_norm over head_dim. If any of the five looks different in your installed version, that difference is the fact to record.
