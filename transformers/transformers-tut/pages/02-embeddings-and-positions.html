Module 0 · The object of study

Embeddings and positions: the first residual vector

The stream starts as the sum of two table lookups. Knowing their shapes and seeing the actual numbers makes the rest of the model concrete.

Two lookups

GPT-2 has two embedding matrices. The token embedding wte has shape (50257, 768): one row per vocabulary entry. The positional embedding wpe has shape (1024, 768): one row per position up to the context length. A token with id t at position p enters the model as the vector wte[t] + wpe[p]. There is no multiplication and no nonlinearity; it is two row lookups and an addition. The original Transformer used fixed sinusoidal positions and scaled the embedding by √d_model [Vaswani 2017]; GPT-2 learns both tables and adds them unscaled, which is what the installed code does [transformers GPT-2 code].

Here are the first five coordinates of each piece for the first two tokens of the running prompt:

python labs/anatomy.py embed
wte shape (50257, 768), wpe shape (1024, 768)
position 0, token 464 ('The')
  wte[464][:5] = [-0.0686, -0.0203, 0.0645, -0.0621, -0.1135]  |wte| = 2.720
  wpe[0][:5]   = [-0.0188, -0.1974, 0.0040, 0.0113, 0.0638]  |wpe| = 9.876
  sum[:5]       = [-0.0874, -0.2177, 0.0685, -0.0507, -0.0497]  |sum| = 10.132
position 1, token 3797 (' cat')
  wte[3797][:5] = [0.0100, 0.0366, 0.1640, -0.2185, 0.0285]  |wte| = 3.258
  wpe[1][:5]   = [0.0240, -0.0538, -0.0949, -0.0129, -0.0101]  |wpe| = 5.192
  sum[:5]       = [0.0339, -0.0172, 0.0691, -0.2314, 0.0185]  |sum| = 6.058
max |(wte+wpe) - hidden_states[0]| = 0.00e+00

Check one coordinate by hand: −0.0686 + (−0.0188) = −0.0874, the first entry of the sum. The last line confirms that Hugging Face's hidden_states[0] is exactly this sum (dropout is inactive in eval mode, so nothing else happens before block 0).

The norms tell a story already

At position 0 the positional vector has norm 9.9 while the token vector has norm 2.7: the first residual vector is dominated by "I am at position 0," not by "I am The." At position 1 the two are closer, 5.2 against 3.3. These are facts about this checkpoint's learned tables, read off the weights; they are not a general law. But they illustrate a habit you will need: when you look at a residual vector, ask what it is made of, and measure rather than assume.

Shapes and the batch axis

For a batch of b prompts of length s, wte[ids] has shape (b, s, 768) and the position lookup wpe[0:s] has shape (s, 768), which broadcasts across the batch. The result, shape (batch, seq, d_model), is the shape of the residual stream everywhere in the model until the unembedding. Two consequences follow. First, position p of every prompt gets the same wpe[p]; the model cannot distinguish "position 3 of prompt A" from "position 3 of prompt B" by position alone. Second, inputs longer than 1,024 tokens have no row to look up: the context window is a property of the table's size, not a soft limit.

Batching prompts of unequal length requires padding and an attention mask so padded positions are ignored. This course keeps batch size 1 to avoid that machinery; the capstone accepts a batch axis but is tested on one prompt.

What the embedding is not

The embedding row for " cat" is not "the representation of cat" in any later layer. It is the starting point that every block then adds to. By block 6 the vector at that position is the embedding plus twelve contributions, and the later contributions are larger in norm than the embedding itself, as the next lesson shows. The embedding does have one special role: because GPT-2 ties its output matrix to wte (lesson 09), the same rows are also the directions that the final residual vector is dotted with to produce logits.

In interpretability work

Position embeddings are a confound for any claim about tokens. If a probe reads a direction that happens to align with wpe[0], it will fire on whatever token comes first. When testing a claim about a token, vary its position; when testing a claim about a position, vary the token. The control for a token claim is the same token at other positions.

Pitfall

Indexing wpe with the token id or wte with the position. Both tables have width 768, so the shapes broadcast and nothing crashes; the numbers are simply wrong. Assert the index ranges: token ids are below 50,257, positions below 1,024.

Check your understanding

A batch holds the prompts "The cat" and "A cat". Which of the two tokens at position 1 receive the same positional vector, and which receive the same token vector?

Reveal the reasoning

Both prompts have " cat" (token 3797) at position 1, so both receive wpe[1] and both receive wte[3797]; the two residual vectors at position 1 are identical before block 0. At position 0 the tokens differ (464 versus the id for "A"), so the token vectors differ while the positional vector wpe[0] is shared. Attention will later make the position-1 vectors differ, because they attend to different position-0 tokens.

Practice

Run embed on a different prompt and confirm which coordinates match the running prompt at position 1 and which do not.

python labs/anatomy.py embed "A cat" --positions 2
What to look for

wte[3797][:5] and wpe[1][:5] are identical to the running prompt, so the sum at position 1 is identical: [0.0339, -0.0172, 0.0691, -0.2314, 0.0185]. Position 0 differs because the token id differs, although wpe[0] is the same vector in both runs.
