Module 2 · MLPs and the output

Unembedding and logits: from the stream to a distribution

A final layer norm, one matrix multiply against the embedding table, and a softmax. The logit lens applies that same ending to every earlier layer.

The last three steps

After block 11 the residual stream passes through ln_f (lesson 04) and is multiplied by the unembedding matrix W_U of shape (768, 50257). The result is one logit per vocabulary entry per position. GPT-2 ties this matrix to the token embedding: lm_head.weight is literally the same tensor as transformer.wte.weight, transposed in use, as the config's tie_word_embeddings=True and a pointer comparison both show. Vaswani et al. shared the embedding and pre-softmax matrices in the original Transformer too [Vaswani 2017]. So the logit for token t is the dot product of the final normalised residual with t's embedding row.

logits = ln_f(resid_post.11) · WU, WU = wteᵀ, shape (batch, seq, 50257)
p(next = t) = exp(logitt) / Σu exp(logitu)

The softmax turns a row of logits into probabilities. Two of its properties are worth having in hand:

python labs/anatomy.py softmax-demo
logits [2.0, 1.0, 0.0] / T=1.0: softmax = [0.6652, 0.2447, 0.0900]
logits [2.0, 1.0, 0.0] / T=2.0: softmax = [0.5065, 0.3072, 0.1863]
logits [2.0, 1.0, 0.0] / T=0.5: softmax = [0.8668, 0.1173, 0.0159]
adding 10 to every logit changes nothing: [0.6652, 0.2447, 0.0900]

Check the first line by hand: e² = 7.389, e¹ = 2.718, e⁰ = 1, sum 11.107, so the probabilities are 0.665, 0.245, 0.090. Adding a constant to every logit cancels in the ratio, which is why TransformerLens's center_unembed (subtracting the mean of W_U's columns so logits are mean-zero) changes every logit but no probability. Temperature divides the logits before the softmax; lesson 12 uses it for sampling.

The logit lens

Nothing stops you from applying ln_f and W_U to the residual stream after block 5 instead of block 11. The result is what the model would predict if the remaining blocks did nothing. nostalgebraist's 2020 post made this the "logit lens" and observed that in GPT-2 the intermediate predictions converge toward the final output, often well before the last layer [nostalgebraist 2020]. The command below does it for every block at the last position of the running prompt:

python labs/anatomy.py logit-lens

Read it as a trajectory. After block 0 the stream at mat still mostly points at the embedding of mat itself, so the lens predicts ' mat': tied embeddings make the input token the default prediction before anything has been written. Blocks 1–7 move toward word-completions of mat (matrices, mathematically, matting); the model has not yet "decided" that the word is complete. From block 8 the predictions are plausible next words, and the final answer is a comma at 0.237. The last line confirms that the lens at block 11 is exactly the model's own output.

What the lens does and does not show

The logit lens is a projection: it reads the stream in the basis the unembedding uses, and ignores everything orthogonal to it. A direction the later blocks need, but which does not itself align with any token's embedding, is invisible to the lens. So "the model knew the answer by layer 8" is a claim about one projection of the stream, and the reverse ("the model had not decided by layer 4") is weaker still, because the information may be present in a form the lens cannot read. The lens is a first application of the additive structure, not a readout of what the model "believes."

In interpretability work

Because logits are a linear function of the final normalised stream, and the stream is a sum of writes, each write's contribution to a logit difference (say, the correct token minus a distractor) is a scalar you can compute per head and per neuron. That is direct logit attribution, and it is exact up to the layer-norm scale. The prediction test for a "this head boosts the correct answer" claim is that its attribution is positive on held-out prompts, against a random-head control.

Pitfall

Comparing raw logits across tools or across processing modes. TransformerLens's default compatibility mode centres the unembedding, so its logits differ from Hugging Face's by a per-position constant (108.9 on the running prompt, lesson 13), while every probability and every argmax agrees. Compare log-probabilities or logit differences, which are invariant to that constant.

Check your understanding

The lens after block 0 gives the input token itself with probability 0.92. Is that evidence that block 0 "copies the input," and what is the control?

Reveal the reasoning

Mostly no. Tied embeddings mean the stream after embedding already has a large dot product with its own token's unembedding row, before any block has acted; the lens after block 0 inherits that. The control is the lens applied to the stream before block 0 (hidden_states[0] through ln_f): if it already predicts the input token strongly, block 0 added little to that. A claim about block 0 should compare its write's projection with the embedding's projection.

Practice

Run the lens on a prompt with a strongly expected continuation. Note at which block the final top token first appears and whether it stays.

python labs/anatomy.py logit-lens "The capital of France is"
What to look for

The output shows the layer at which " Paris" (if the model predicts it) first enters the top three and how its probability moves; whether it stays or is displaced is the interesting part, and it varies by prompt. Any block-level claim you form from one prompt is a hypothesis to test on a held-out set of capital-city prompts, not a finding.
